## 文档维护规则

1. **状态只写一处**：测试数、APK/exe 体积、Release 版本只在 `交接文档.md` 和发布页维护；其他文档引用，不复制整组数字。
2. **规划与历史不重写**：`需求文档.md`、`功能发展方案.md`、`04-评审/*`、旧任务书保留原文，只追加“进展/已落地”标注。
3. **对外数字随发布更新**：`05-宣传/*` 的数字必须与 `交接文档.md`、GitHub Release 附件一致；发现冲突以实测和 Release 为准。
4. **不再新增一次性报告**：同类排查并入对应专题文档的附录；只有需要独立长期维护的机制才新建文档。
5. **文档变更也要验链**：提交前检查相对链接、表格列数和代码路径；历史版本号/旧测试数只允许出现在明确标注“历史”的段落。

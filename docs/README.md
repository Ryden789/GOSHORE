## 更权威的两个入口

- **`../交接文档.md`** —— 项目现状的**唯一权威来源**：最新提交、APK 体积、测试基线、
  数据库 Schema、回归命令、已知问题。
- **`../README.md`** —— 面向使用者的项目说明：功能清单、题库规模、快速开始、项目结构。

## 文档时效性约定

1. **规划类文档不做事后改写**：`功能发展方案.md`、`开发任务手册.md`、`04-评审/*` 的原文保持原貌，
   只在其上**追加**进展标注。这样能看出当初的判断是什么、后来验证成了什么样。
2. **数字以实测为准**：文档里出现的用例数、校验器个数、APK 体积、代码行数，
   如有冲突一律以 `交接文档.md` 与仓库实际内容为准。
3. **每轮功能交付后同步更新**：`交接文档.md`（状态与基线）→ `02-设计` 附录 C（提交号与实测）
   → 受影响的宣传材料（对外数字）。

> 文档口径说明：当前基线为 `pytest 1001 passed`、`AI 评测 33 条 100.00 分`、
> `15 个静态校验器 EXIT=0`、`E2E 33 路由 / 79 项断言全通过`（2026-10-21 实测），随每次交付滚动更新。
> 历史基线（2026-10-09）为 843 passed / 79 项断言、（2026-10-20 上午）852 passed / 78 项断言、（2026-10-21 P3 时）915 passed，均已被取代。
> 代码规模口径：纯代码 **154 文件 / 64,865 行**（剔除 `static/vendor/` 与构建产物，含测试与 15 个校验器），另有数据文件 8,314 行。
> 桌面分发：GitHub Release [v2026.10.26](https://github.com/Ryden789/GOSHORE/releases/tag/v2026.10.26) 附 exe 与 `content-sample.db`。

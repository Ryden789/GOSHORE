## 一、项目概述

### 1.1 产品定位

一款**本地优先、AI 驱动的"个人题库精读工作台"**：读取用户已有的 Obsidian 本地题库（约 1.1 万道深度标注真题），用 AI 完成粉笔生态内做不到、做不好或要收费的事——

- 讲粉笔 App 里**没有的题**（你自己的私有题库）；
- 比通用 AI 助教讲得**更深**（基于每题已有的推理链/最快解法/易错点/母题抽象底稿）；
- **质疑官方解析**（库内 1573 条疑点的复核工作台）；
- **无限次、模型自选、数据不出本地**（无会员墙、无次数限制）；
- 提供粉笔没有的**速算专项训练**。

### 1.2 与粉笔的关系：补充，不替代

| 事项 | 用粉笔 | 用本产品 |
| --- | --- | --- |
| 日常刷题、套卷模考、估分排名 | ✅ | ❌ 不做 |
| 粉笔题库内的题看基础解析 | ✅ | — |
| 粉笔题库之外的题、自己整理的题要讲透 | ❌ | ✅ |
| 干扰项逐一拆解、多解法对比、反复追问 | 受会员/次数限制 | ✅ |
| 质疑官方答案、争议题独立复核 | ❌ 不可能教用户质疑自己 | ✅ |
| 速算/计算速度专项训练 | ❌ | ✅ |
| AI 生成同考点变式题 | ❌ | ✅ |

### 1.3 设计原则

1. **本地优先**：题库、笔记、学习数据存本地；仅在调用云端模型时传输必要文本；
2. **底稿驱动**：AI 输出必须建立在库内结构化标注之上，不允许脱离底稿自由发挥；
3. **可验证**：AI 给出的每一步计算都要可复算，存疑时明确标注"不确定"，不编造；
4. **克制**：不做课程、社区、排行榜、模考系统。

## 二、核心资产：本地题库盘点

题库位置：`D:\人文\kaogongzhentizhengliu`（Obsidian vault，Markdown 纯文本，约 2 万+ 节点、2 万余张配图，完全离线）。

### 2.1 题量分布

| 模块 | 大类数 | 考点数 | 真题数 |
| --- | --- | --- | --- |
| 资料分析 | 7 | 3353 | 3569 |
| 判断推理 | 5 | 7022 | 7713 |
| **合计** | 12 | 10375 | **11282** |

覆盖 34 个地区、2008–2026 年真题。

### 2.2 数据分层（每层都是 AI 可用的结构化上下文）

| 目录 | 内容 | 关键字段 |
| --- | --- | --- |
| `10-真题/` | 每题一篇深度标注 | frontmatter：qid、试卷、地区、年份、考点、tags；正文：**问法模型、推理链（分步）、最快解法⚡、易错点⚠、母题抽象🧩、同类特征、相关题（带相关度）、题干、选项、官方解析、给定材料** |
| `15-材料/` | 资料分析材料档案 | 时间口径、单位与换算、结构拆解、阅读陷阱、小题群关系、材料原文、关联小题 |
| `20-考点/` | 考点 MOC | 核心立场（母题抽象集合）、跨卷聚合真题列表、疑点待复核区 |
| `30-疑点复核/` | 疑点总清单 1573 条 | 每条含 qid、地区、年份、考点路径、疑点描述（数据缺失/解析笔误/答案争议/口径分歧等） |
| `90-图片/` | 题目图、公式图 2 万余张 | 按相对路径被笔记引用 |

### 2.3 这套资产的独特价值（竞品无法复制）

1. **每题都有"教研底稿"**：推理链写到第 5 步、最快解法单独标注、坑值（如误算基期量恰好是干扰项 D）明确指出——AI 基于它讲题，深度天然高于基于一份标准答案的泛化讲解；
2. **自带知识图谱**：题目↔考点↔材料的 wikilink + 相关度打分，检索不必完全依赖向量相似度；
3. **批判式疑点库**：1573 条对官方解析/题干的质疑，是最稀缺、最有训练价值的数据；
4. **材料层档案**：口径、单位、陷阱的结构化记录，AI 讲资料分析时能回答"这题的坑在哪"。

### 2.4 已知约束

- vault 使用说明注明：**手工修改笔记会在下次导出时被覆盖**，修正需"从数据侧进行"——AI 生成内容如何写回 vault 需专项确认（见第十章 Q3）；
- 部分疑点题的增速/数值在转录时缺失（图片未识别），这类题 AI 也无法精确复算，需明确标记。

## 三、竞品对标与差异化（2026 年现状）

粉笔已上线 AI 助教"**粉笔头**"（自研垂域大模型），具备：题目解析追问、知识点讲解、错题归因、备考计划生成、面试点评；另有 AI 刷题班（¥299–499，捆绑一年 SVIP）、申论智能批改等。

**因此"做一个 AI 讲题功能"不构成差异。本产品的差异锚点为：**

| 差异锚点 | 说明 |
| --- | --- |
| ① 本地私有题库 | 粉笔头只能讲粉笔题库；本产品讲用户 vault 里的任意题，且持续随 vault 更新 |
| ② 深度底稿讲解 | 基于推理链/最快解法/母题抽象/材料档案组织讲解，而非从标准答案现编 |
| ③ 批判式复核 | AI 独立验算官方解析、协助消灭 1573 条疑点，立场是"帮用户质疑"而非"维护标准答案" |
| ④ 模型自由、无次数限制 | 支持任意 OpenAI 兼容接口（DeepSeek/通义/GLM 等）与本地模型（Ollama），用户自带 key，无会员墙 |
| ⑤ 本地隐私 | 笔记、错题、自建内容不上云；云端调用可关闭、可替换为本地模型 |
| ⑥ 速算训练场 | 粉笔无对应专项产品 |

> 来源：粉笔官方页面《粉笔AI老师粉笔头是什么》（2026-08-30）、粉笔课程页、中国日报网《2026粉笔教育》（2026-04-14）。

## 四、目标用户与使用场景

### 4.1 目标用户

- 首要用户：**本产品作者本人**（备考事业单位联考 C 类，数量关系正确率高但做题慢，资料分析计算速度待提升）；
- 潜在用户：拥有自己题目积累、希望用 AI 精读私有题库的考生（是否产品化分发见第十章 Q5）。

### 4.2 核心场景

| 场景 | 时长 | 功能 |
| --- | --- | --- |
| 做完粉笔的题，把存疑/错题放进 vault，让 AI 精读 | 每题 3～8 分钟 | AI 讲题（精读模式）、追问 |
| 一批错题攒完，找共性问题 | 10 分钟 | AI 批量归因、薄弱点画像 |
| 碎片时间练计算速度 | 1～3 分钟 | 速算训练场 |
| 周末集中处理疑点清单 | 20～60 分钟 | 疑点复核工作台 |
| 某考点掌握不牢，需要同类变式题 | 10 分钟 | AI 变式题生成 |
| 检索本地题库、浏览考点 MOC | 随时 | 题库浏览与全文检索 |

## 五、功能需求

> 优先级：**P0 = MVP 必做；P1 = 第二阶段；P2 = 后续**。

### 5.1 题库接入与索引（P0）

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| I-01 | vault 接入 | 配置本地 vault 路径，首次启动扫描全部 Markdown，按 frontmatter `类型` 识别真题/考点/材料/清单 |
| I-02 | 结构化解析 | 解析每题各章节（推理链、最快解法、易错点、母题抽象、相关题、题干/选项/材料），入库为结构化字段而非整段文本 |
| I-03 | 索引与检索 | SQLite 存储；FTS5 全文检索；支持按模块/大类/考点/地区/年份/qid 筛选；题干图片按相对路径正常渲染 |
| I-04 | 增量更新 | 监听 vault 文件变化，更新索引；重新导出后自动重建变更部分 |
| I-05 | 关联图谱利用 | 解析 wikilink 与"相关题（相关度）"，作为 AI 检索的首要来源（结构化召回优先，语义召回补充） |

### 5.2 AI 讲题（P0，核心功能）

#### 5.2.1 三种讲题模式

| 模式 | 内容结构 | 适用 |
| --- | --- | --- |
| **速讲** | 题型判定（问法模型）→ 解题关键一步 → 答案 | 快速复盘、已基本掌握的题 |
| **精读**（默认） | ①考点与问法判定 → ②推理链逐步展开（每步说明依据并引用材料原文位置）→ ③最快解法⚡及适用条件 → ④四个选项逐一分析：正确项依据 + 3 个干扰项各是什么陷阱（坑值/偷换口径/无中生有/单位错误）→ ⑤母题抽象一句话总结 | 错题、存疑题 |
| **卡点讲** | 用户先选择/输入自己错选的选项或卡住的步骤，AI 只讲偏差部分，并指出该错误对应的典型思维误区 | 知道自己大概卡在哪 |

#### 5.2.2 多轮追问

- 讲完保留对话上下文，支持："B 为什么不对""第三步没懂，换个说法""如果材料没有这句话还能做吗""这题和 qid 2261936 有什么区别"；
- 快捷追问按钮预置高频问题（再讲一遍/举个例子/只看选项陷阱/常规法对比最快法）。

#### 5.2.3 个性化与输出形式

| 编号 | 功能 | 优先级 |
| --- | --- | --- |
| A-01 | 讲解时带入用户画像：历史错题、掌握度、常犯错因，避免讲用户已掌握的内容 | P1 |
| A-02 | 讲解深度可切换：小白式（补基础概念）/ 备考式（默认，直接讲题） | P1 |
| A-03 | Markdown 排版：公式用 LaTeX 渲染，关键结论高亮 | P0 |
| A-04 | 语音朗读讲解（TTS） | P2 |
| A-05 | 图形推理题：支持多模态模型读取题目图片进行讲解（需接入视觉模型）；无视觉模型时提示用户并只基于文字部分 | P1 |

#### 5.2.4 讲题质量红线（验收标准）

1. 题型判定、公式、数据引用必须与库内底稿一致；底稿与 AI 判断不一致时，**同时展示两方说法**，不得静默覆盖；
2. 所有数值计算必须在输出中保留可复算的算式；模型须经"计算校验"环节（可调用确定性计算工具二次验证）；
3. 材料缺失值题（vault 已标注的疑点题）必须明确告知"该数值缺失，结论依官方答案反推"；
4. 单次讲解中模型不得虚构材料中不存在的数据、年份、政策。

### 5.3 AI 题目分析（P0）

| 编号 | 功能 | 描述 | 优先级 |
| --- | --- | --- | --- |
| N-01 | 单题分析卡 | 自动生成：考点判定、问法模型、干扰项构造类型、阅读量/计算量评级、建议用时、与哪几道母题同构 | P0 |
| N-02 | 标注一致性校验 | AI 结论与 vault 已有标注（考点标签、母题抽象）比对，不一致时进入"待确认"列表 | P1 |
| N-03 | 批量命题分析 | 利用 34 地区 × 18 年数据，回答："某考点在广东卷的出现频次""近 3 年增长量计算的问法变化"等，输出图表 | P1 |
| N-04 | 全库考点体检 | 批量扫描，输出：标注缺失题、疑似重复题、考点命名不规范（如同义考点多名）清单 | P2 |

### 5.4 AI 复盘助手（P1）

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| F-01 | 批量错题归因 | 用户选定一批错题，AI 跨题分析共性："这 20 题中 12 题栽在单位/口径，6 题是把基期当增长量"，输出错因结构，而非逐题复述 |
| F-02 | 薄弱点画像 | 按考点聚合错题与正确率，生成个人薄弱 Top N，并解释每条结论所依据的题目 |
| F-03 | 复盘周报 | 本周消灭错题数、新增疑点、速算用时变化、下周建议（结论必须可回溯到具体题目） |
| F-04 | 追问式复盘 | 对归因结论可追问："我觉得不是单位问题，是审题问题"——AI 需重新调取题目论证或承认判断偏差 |

### 5.5 疑点复核工作台（P1，特色功能）

把 `30-疑点复核/疑点清单.md` 的 1573 条疑点做成可管理的工作台：

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| Q-01 | 疑点入库 | 解析清单，按模块/大类/疑点类型组织，状态流转：待复核 → 已确认/已排除/需人工 |
| Q-02 | AI 独立复核 | 对每条疑点：调取原题、材料、官方解析 → **独立重算**（计算类调用确定性计算工具）→ 输出复核结论（数据缺失/解析笔误/答案争议/口径分歧/原题无误）+ 证据链 |
| Q-03 | 人工终审 | 人工确认 AI 结论后勾选；复核结论支持批量通过、单条编辑 |
| Q-04 | 状态写回 | 勾选状态按 vault 规则写回对应考点笔记的「疑点待复核」区（依赖第十章 Q3 的结论） |
| Q-05 | 争议题专题 | 对"答案争议"类（粉笔与其他机构答案不同的题）单独归档，展示多方解法，作为拔高训练材料 |

### 5.6 AI 变式题生成（P1）

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| V-01 | 同考点变式 | 基于母题抽象改编：替换数字与材料情境、保持考点与解法结构，每次生成 1～5 题 |
| V-02 | 答案自检 | 生成题的答案必须经独立计算校验（速算/资料题走确定性程序校验，逻辑题走模型交叉验证），校验不过不出题 |
| V-03 | 难度调节 | 同考点生成"更简单/同难度/更绕（多一层口径陷阱）"三档 |
| V-04 | 入库 | 做完且质量认可的变式题按 vault 格式导出为 Markdown（路径与命名遵循 vault 规范） |

### 5.7 速算训练场（P0，粉笔空白功能）

目标：直接服务资料分析，每轮 1～3 分钟，把计算练成肌肉记忆。题目由**程序按规则生成**（无版权问题、无限题量、答案由程序确定，不存在 AI 算错风险）。

| 编号 | 题型 | 说明 |
| --- | --- | --- |
| S-01 | 基础四则 | 2～4 位数字加减乘除，可配位数、是否进位/借位 |
| S-02 | 截位直除 | 形如 4832/1.137，配 4 个选项，训练按选项差距决定截几位 |
| S-03 | 特殊分数换算 | 分数 ↔ 百分数互化（1/7≈14.3%、3/8=37.5% 等高频值） |
| S-04 | 增长率/基期 | 已知现期、r 求基期；已知基期、现期求 r |
| S-05 | 增长量 | 现期 × r/(1+r)，含百化分专项 |
| S-06 | 60 秒挑战 | 连续出题计时，结束给正确数与平均每题用时 |
| S-07 | 数据记录 | 按题型记录正确率、平均用时、最佳成绩，输出用时趋势曲线 |

可配置：题型多选、题量、数字位数、难度。验收要点：数字键盘直输、判定零延迟；错题进入本地错题集。

### 5.8 轻量做题（P1，够用即可）

不做模考/排行榜，只服务本地题库：

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| T-01 | 题库浏览 | 按模块/大类/考点树浏览，阅读考点 MOC 与材料档案（含图片渲染） |
| T-02 | 本地作答 | 题干+选项作答 → 立即对答案 → 一键进入 AI 讲题；记录单题用时 |
| T-03 | 标记收藏 | 标记"疑问/待盘"，自动汇集为待办清单 |
| T-04 | 手动录题 | 粘贴题干/选项/解析存为 vault 格式 md，拍照/截图 OCR 辅助（P2） |

### 5.9 学习数据（P1）

- 做题量、正确率、单题用时（按模块/考点）；
- 速算用时趋势；疑点复核进度；
- 学习日历与连续天数；
- 数据全部本地存储，可导出。

## 六、AI 上下文（RAG）构造要求

讲题/分析时，上下文按以下优先级组装，控制 token 成本：

1. **本题结构化全文**：题干、选项、材料、推理链、最快解法、易错点、母题抽象；
2. **结构化关联**：相关题（按 vault 相关度）、所属考点 MOC 的核心立场、所属材料档案（口径/陷阱）；
3. **语义召回补充**：对母题抽象/考点文本做向量化（仅对这两类短文本建向量索引，约 1 万条，成本低），召回同构题；
4. **用户数据**：该题历史作答、错因、个人薄弱点（P1）。

要求：AI 回答中的每个事实性结论应可指向上文某个来源，不允许只凭模型常识作答。

## 七、模型接入策略

| 模式 | 渠道 | 说明 |
| --- | --- | --- |
| 云端（默认） | 任意 OpenAI 兼容接口：DeepSeek、通义千问、GLM、OpenAI 等 | 用户在设置中配置 endpoint / key / 模型名，可随时切换；不同功能可选不同模型（讲题用强模型、速讲用便宜模型） |
| 本地 | Ollama 等本地推理 | 离线可用、完全隐私；讲题深度受本机配置限制 |
| 多模态 | qwen-vl / GLM-4V / GPT-4o 等 | 仅图推图片理解时调用 |

成本控制：缓存同题讲解结果；速讲与精读分模型；上下文按第六章裁剪。

## 八、非功能需求

1. **性能**：题库检索 ≤ 300ms；讲题首 token 延迟取决于模型，流式输出；本地万题索引内存占用可控；
2. **平台**：Windows 桌面端优先（形态最终见第十章 Q1）；
3. **隐私安全**：API key 本地加密存储；云端调用内容用户可见、可关闭；支持纯本地模型模式；
4. **可靠性**：索引损坏可重建；AI 服务失败不影响题库浏览；
5. **可维护**：题库解析规则与 vault 结构解耦，vault 结构变更时只需调整解析配置。

## 十、待确认问题

1. **平台形态**：首选 Windows 桌面端（Tauri / Electron，轻量建议 Tauri）？还是先做本地 Web 服务（浏览器访问）快速验证？
2. **模型与预算**：你目前有哪家 API key？是否接受本机跑 Ollama（机器配置/显卡）？这决定 MVP 默认讲题质量与离线程度。
3. **vault 双向写回**：vault 由"工作台"自动生成且手工修改会被覆盖——这个"工作台/数据侧"是什么（数据库 + 导出脚本）？AI 的复核勾选、变式题入库应写回它的数据侧而非直接改 md，需要你提供该工作台的信息或决定 MVP 只做只读 + 独立状态存储。
4. **题库扩充**：后续是否会补言语理解、数量关系、常识模块？解析器需要按模块预留差异。
5. **使用范围**：仅个人自用，还是未来分发给其他考生？自用可省略账号体系并深度单机化，产品化则需考虑 vault 打包分发的版权问题（题源与解析的合规性）。
6. **申论/综应**：是否需要 AI 批改？当前题库不含主观题，建议暂不做。

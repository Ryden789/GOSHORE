## 一、现状盘点与核心判断

### 1.1 已具备的能力（不重复造轮子）

| 层 | 已有能力 |
|----|---------|
| 题库 | 23,491 道题目（其中真题 12,393 道）、10 类论证谬误、辨析卡库 1,150 张、时政模块 |
| AI | DeepSeek 讲题、AI 命题（词语填空/变式题/模拟卷）、申论批改、AI 预归因 |
| 训练 | 真题套卷倒计时、速算、错题本（移出/恢复）、艾宾浩斯复习、每日开门题、断点续做、单手翻题、考场模式涂卡 |

| 工程 | 双端共享块 + 静态校验器、schema 版本化迁移、pytest **748 条**、E2E 33 路由 / 72 断言、热更新包、APK 独立运行版 |

### 1.2 三个核心判断（决定方向）

1. **不与粉笔拼"题海量级"**——拼不过，也没必要。要拼**"AI 把本地题库榨干"**：每道错题都能归因、每个薄弱点都能追踪、每段时间都能产生增量。
2. **主观题是 C 类最大痛点，也是 AI 最大机会**——综应 150 分里主观题占大头，人工批改贵且慢，AI 批改是天然蓝海。
3. **单机版是护城河，但单机也意味着没有网络效应**——先用"个人 AI 教练"做深价值，再谨慎引入轻社交，不做重社区。

### 1.3 发展总原则

- **价值优先**：每个功能必须回答"帮用户多拿几分 / 省多少时间"
- **增量交付**：每阶段独立可用，不憋大招
- **AI 原生**：能让 AI 做的不让用户手工做
- **双端同步**：新功能原则上双端一起上，避免再次分叉

## 三、阶段一：AI 教练深化（1~2 月）

### 功能 1.1　自适应推题（错题驱动的智能出题）

**用户价值**：不再"刷到哪算哪"，系统根据掌握度自动调配题目，弱项多练、已掌握少练。

**现状**：组卷靠随机 + 手动筛选；错了只进错题本，不影响后续推题。

**功能点**：
1. 为每道题维护一个**掌握度分数**（0~1），初始 0.5
   - 答对 +0.15，连对加成；答错 -0.25；长时间未复习衰减
2. 推题时按掌握度加权抽样：掌握度越低被抽中概率越高
3. 用户可在刷题页选"智能模式 / 顺序模式 / 随机模式"
4. 首页显示"今日推荐练习"模块（直接组好 15 题）

**技术实现**：
- `app/db.py` 新增表：
  ```sql
  CREATE TABLE IF NOT EXISTS mastery(
      doc_id INTEGER PRIMARY KEY,
      score REAL DEFAULT 0.5,
      updated_at REAL,
      correct_streak INTEGER DEFAULT 0
  );
  ```
- 新增函数：
  - `update_mastery(doc_id, is_correct)` —— 更新分数与连对
  - `adaptive_paper(module, n)` —— 加权随机抽题（`WHERE kind='真题'`，用 `ORDER BY (?)` 或在 Python 里做权重抽样）
  - 衰减：`/api/stats` 调用时按天数批量衰减
- schema 版本升到 **3**，走 `_migrate()`
- 前端：`static/m/m.js` 的 `renderPractice` 加模式切换；桌面 `static/app.js` 同步

**接口**：
- `POST /api/paper/adaptive` body `{module?, n}` → `{ids:[]}`

**工作量**：中（约 2~3 天）
**验收**：连错的题下次被抽中概率明显变高；掌握度表有数据；双端可切模式。

---

### 功能 1.2　错题 AI 归因 2.0（从"一句话"到"错因分类 + 知识点定位"）

**用户价值**：现在 AI 预归因只给一句话；升级后自动归类错因（概念不清/计算失误/审题偏差/公式用错/时间不够），并统计高频错因。

**功能点**：
1. 答错后 AI 返回**结构化归因**：
   ```json
   {"category":"概念不清","specific":"混淆增长量与增长率","kaodian":"增长量计算","advice":"先背公式再练5题"}
   ```
   若已有手动错因则不覆盖。
2. 错题本顶部显示**错因分布饼图**（纯 SVG/CSS，不引图表库）
3. 周报新增"高频错因 Top3"

**技术实现**：
- `app/main.py` 的 wrong-reason-ai 接口改 prompt 要求返回 JSON，解析后落库
- `answers` 或错因表加 `ai_category` 字段（迁移）
- `app/db.py` 新增 `wrong_reason_distribution()` 聚合
- 前端错因分布图用内联 SVG 圆环 + 图例（书房纸墨配色）

**工作量**：中（2 天）
**验收**：答错后自动出现分类；分布图各部分占比加起来 100%；AI 偶发返回非 JSON 时有兜底。

---

### 功能 1.3　综应主观题 AI 批改 2.0

**用户价值**：这是**全项目最高价值功能**。现有申论批改偏整体打分，升级为"要点逐条命中 + 档位 + 可提分建议"，逼近真人批改。

**功能点**：
1. **要点命中表**：把参考答案拆成得分点，逐点标"命中 / 部分命中 / 缺失"，给出每点得分
2. **四维评分**：要点完整性、逻辑结构、语言规范、字数与格式
3. **改写示范**：AI 把用户答案的薄弱段落改写一遍（标红新增、标蓝删改）
4. **历史提分曲线**：同一题型历次批改分数趋势
5. 支持科技文献摘要题、论证评价、议论文三类各有专属评分维度

**技术实现**：
- `app/essay_rubric.py` 扩展评分 rubric 与 prompt（强制 JSON schema 输出）
- `app/main.py` 的 essay-grade 流式接口增加结构化阶段
- 新表 `essay_grades` 扩展字段：`points_json`、`rewrite_json`
- 前端批改结果页：要点表 + 分数卡 + 改写对照（`<ins>`/`<del>` 样式）
- 批改必须支持"无参考答案时 AI 自拟要点"兜底

**工作量**：高（约 5~7 天，建议拆 3 个迭代：要点表 → 改写 → 曲线）
**验收**：拿 3 篇真实作答对比人工批改，要点召回率 ≥85%，分数偏差 ≤10%；JSON 解析失败率 <5%。

---

### 功能 1.4　知识掌握度图谱（考点级，不只是题目级）

**用户价值**：看清自己"哪些考点会、哪些不会"，告别模糊感觉。

**功能点**：
1. 以**考点（kaodian）为节点**聚合正确率、题量、最近练习时间
2. 三色标记：绿（掌握 ≥80%）/ 黄（50~80%）/ 红（<50% 或未练）
3. 按模块展示图谱（列表式，避免复杂图形渲染）
4. 点任一考点 → 直接进入该考点专项练习

**技术实现**：
- `app/db.py` 新增 `kaodian_mastery(module?)`，复用现有 answers 聚合
- 前端新页面 `#/mastery`，双端加入口（总览/复习巩固分组）
- 纯 HTML 表格 + 色点，不引图库

**工作量**：中低（1.5 天）
**验收**：图谱数据与搜索页模块筛选的正确率能对上；点击节点可练题。

## 四、阶段二：数据智能 + 内容自动化（3~6 月）

### 功能 2.1　能力雷达与学习路径规划

**用户价值**：一张雷达图看五模块水平；系统生成"未来 14 天每日练什么"的计划。

**功能点**：
1. 五维能力雷达（言语/判断/数量/资料/综应），内联 SVG 六边形
2. **14 天个性化计划**：根据考试日期倒排，弱项加权，每日给出题量与模块
3. 计划可打勾完成，完成度滚动调整后续计划
4. 首页"今日计划"卡片

**技术实现**：
- `app/db.py` 新增 `ability_radar()`
- 新建 `app/planner.py`：输入考试日期、可用时长，输出每日任务（纯算法，不依赖 AI，省成本）
- 表 `study_plan(day, module, n, done)`
- 前端雷达图 + 计划页

**工作量**：中（3~4 天）
**验收**：无历史数据时给通用计划；有数据时弱项明显加权；计划 14 天总量合理。

---

### 功能 2.2　时政内容自动化流水线（已有半成品脚本）

**用户价值**：时政靠手工更新太累；实现"抓取 → AI 出题 → 入库 → 热更"全自动。

**现状**：`tools/` 下已有 scrape / batch_gen / import 脚本，需串成一条链并定时运行。

**功能点**：
1. 一条命令跑完：人民网抓取 → 按月归档 → AI 生成选择题/要点题 → 写库
2. 生成 **manifest** 标注新增时政条数
3. 支持增量：已抓取的 URL 去重
4. 时政"学习模式"：先看新闻摘要 → 再做对应题
5. （可选）Windows 计划任务每周自动跑一次

**技术实现**：
- 整合 `tools/scrape_people_shizheng.py`、`batch_gen_shizheng.py`、`shizheng_to_db.py` 为 `scripts/update_shizheng.py`
- 去重表或 URL 唯一索引
- AI 批量出题控制并发与重试（已有经验：先定答案再倒推）

**工作量**：中（2~3 天）
**验收**：一键跑通，重复运行不产生重复题；无网/无 Key 时优雅退出。

---

### 功能 2.3　面试模块（结构化面试 + AI 模拟考官）

**用户价值**：笔试后还有面试，用户生命周期延长；AI 模拟考官是稀缺功能。

**功能点**：
1. 结构化面试真题库（综合分析/组织管理/应急应变/人际沟通/自我认知五类）
2. **AI 语音/文字考官**：出题 → 用户录音或写答案 → AI 按评分表点评
3. 答题计时（思考 1 分钟 + 作答 3 分钟）
4. 高分答案示范库

**技术实现**：
- 新表 `interview_questions`、`interview_logs`
- `app/main.py` 新增 interview 路由组
- 录音用浏览器 MediaRecorder（WebView 需权限），一期可先只做文字作答
- 前端新模块分组

**工作量**：高（5 天，录音再 +2 天）
**验收**：五类题都能练；AI 点评包含"内容/逻辑/表达"三维。

---

### 功能 2.4　考场模式与标准化答题卡

**用户价值**：最大化还原真实考试，减少考场紧张失误。

**功能点**：
1. **考场模式**：全屏、固定 90/120 分钟、不可查资料、交卷前 5 分钟提醒
2. **答题卡**：题号网格，点题号跳题，已答/未答/标记三色，实时统计
3. 交卷后统一结算（不再做一题判一题）
4. 支持"涂卡练习"：资料分析等只填答案的题用答题卡录入

**技术实现**：
- 复用 `runPaper`，增加 `exam_mode` 参数，结算延迟到交卷
- 答题卡组件（HTML grid + 状态 map）
- 桌面端用 Fullscreen API

**工作量**：中（3 天）
**验收**：答题卡跳题正确；未答题交卷有二次确认；计时准确。

---

### 功能 2.5　AI 多轮追问式讲题（"苏格拉底式"教学）

**用户价值**：不给直接答案，而是反问引导用户自己想通，记得更牢。

**功能点**：
1. 错题页按钮"引导我想"，AI 连续反问（"你觉得这题在考什么？""第三步为什么这么算？"）
2. 用户答得对 → 进阶提示；答不对 → 给更强提示，最终才给答案
3. 对话结束可一键看完整解析

**技术实现**：
- `app/ai.py` 新增引导式 system prompt + 多轮上下文
- 复用现有流式问答接口，前端加模式入口

**工作量**：中低（1.5 天）
**验收**：AI 不直接报答案；最多 6 轮后必给解析，避免卡死。

## 五、阶段三：平台化与轻社交（6~12 月）

### 功能 3.1　iOS / 全平台 PWA

**用户价值**：覆盖苹果用户（目前完全缺失）。

**方案**（按成本排序）：
1. **PWA 优先**：manifest + Service Worker 离线缓存，Safari "添加到主屏"即可，几乎零额外开发
2. 后端部署到云服务器（或保持局域网），iOS 通过网址访问
3. **不推荐**短期内用原生 Swift 重写（Chaquopy 依赖安卓，工作量巨大）

**工作量**：PWA 约 3~5 天（Service Worker 缓存策略是重点）
**验收**：断网能打开已缓存页面；iOS 主屏图标与全屏模式正常。

---

### 功能 3.2　微信小程序（谨慎评估）

**判断**：**先评估再投入**。限制：
- 题库 210MB 远超小程序包体，必须改为"云端 API + 瘦客户端"
- 与"本地离线"定位冲突
- 备案、审核成本

**建议触发条件**：当网页版月活证明需求后，再做小程序引流版（只放高频题 + AI 体验，完整版导流 APP）。

**工作量**：高（2~4 周）

---

### 功能 3.3　题单分享与好友 PK（轻社交）

**用户价值**：低成本引入传播，不做重社区。

**功能点**：
1. **题单分享**：把一组题（如"增长量高频 20 题"）生成分享码/链接，对方打开即练
2. **好友 PK**：同一组题各自计时作答，比正确率与用时（异步 PK，不做实时对战）
3. 分享内容走本地 → 需一个极简云端中转（可用 GitHub Gist 或云函数，只传题 ID 列表，不传题库）

**技术实现**：
- 题单导出为 ID 列表 JSON + 短码
- 新表 `shared_sets`（若上云）

**工作量**：中（3~4 天，含轻量后端）
**验收**：跨设备能打开别人分享的题单；PK 结果正确。

---

### 功能 3.4　独立桌面版（Windows 安装包）

**用户价值**：非技术用户不用装 Python。

**方案**：用 PyInstaller 打包 FastAPI + 启动器，或用 Electron/Tauri 套壳；一键安装、开机自启服务、自动开浏览器。

**工作量**：中（3~5 天，PyInstaller 依赖处理可能反复）
**验收**：干净 Windows 机器双击安装即用。

## 六、优先级矩阵与排期建议

### 6.1 价值 / 成本矩阵

## 七、技术规范（所有新功能必须遵守）

1. **数据库**：新表/新列一律走 `_migrate()` + `SCHEMA_VERSION +1`，禁止散装 ALTER
2. **双端**：新接口桌面（main.py）与移动端（goshor_server.py）同时加；移动端只读 ATTACH 库不可写入
3. **AI 调用**：
   - prompt 要求 JSON 输出时，必须有解析失败兜底
   - 批量生成遵守"先定答案再倒推"原则
   - 无 Key 时必须有降级路径（预置题/自评）
4. **前端**：不引重型图表库，图表用内联 SVG；异步操作防竞态（token / 元素存活检查）
5. **隐私**：API Key 不上前端、不入库明文；个人数据文件不上 Git
6. **测试**：每个核心功能至少加 1 条 pytest，确保 `pytest tests -q` 全绿

## 八、风险与取舍

| 风险 | 应对 |
|------|------|
| AI 批改不准 → 用户不信任 | 明确标注"AI 参考"，保留人工评分对照；持续用真实样本校准 |
| AI 调用成本上升 | 能用算法解决的不用 AI（如学习计划）；高频结果缓存 |
| 功能膨胀 → 双端维护吃力 | 每阶段只开 2~3 条线；做完一个验收一个 |
| 单机定位与社交冲突 | 社交只做异步、轻量，用户数据始终本地优先 |
| APK 持续增大 | 后续图片资源考虑按需下载（热更新包已有基础） |

## 0.2 新增功能必须遵守的规范

1. **数据库**：
   - 新表/新列一律在 `_migrate()` 内追加，并把顶部版本号 +1；在迁移注释里加一行 `vXX：……`。
   - 建表用 `CREATE TABLE IF NOT EXISTS`；加列前先 `PRAGMA table_info` 判断，禁止直接 ALTER 导致重复执行报错。
   - **移动端只读 ATTACH 库**：任何用户私有写入只能写 `my_*` 表（连接到的是个人库），不能假设可写 `shared.documents`。
2. **接口双端同步**：桌面在 `app/main.py` 加路由后，必须在 `android/app/src/main/python/goshor_server.py` 的 `do_GET / do_POST / do_DELETE` 同步，否则 APP 上 404。
3. **AI 调用**：要求 JSON 输出必须有解析失败兜底；无 Key 必须降级；不得因 AI 故障让整页 500。
4. **前端**：
   - 不引入重型图表/UI 库，图表一律内联 SVG。
   - 异步操作防竞态：用请求 token 或操作前判断 DOM 元素仍存在（项目已有竞态教训）。
   - 定时器一律走已有的 `safeTimeout / safeInterval` 并登记，切页自动清理；跨页常驻的（如番茄钟）按现有豁免方式处理。
5. **隐私**：API Key 走 DPAPI，不进前端、不写明文；个人数据文件（`data/goshor.db`、`data/settings.json`）不上 Git。
6. **测试**：
   - 数据层逻辑测 db 函数（用 `temp_db` fixture）；接口测 TestClient（用 `client` fixture）。
   - 测试只跑临时库，`conftest._guard_real_db` 会守卫真实库指纹，别试图绕过。

## 0.3 前端偏好（N4/N5）应放哪里

字号、主题这类**纯前端偏好**，统一用一个前端偏好模块管理，**不必进后端数据库**，但需要：

- 用 `localStorage` 存储，并封装成 `Pref`（项目已有 `Pref.get/set`，见 m.js L1111 用法）。
- 通过在 `<html>` 或 `<body>` 上切换 `data-*` 属性 + CSS 变量生效，保证刷新不闪烁。
- 命名约定：`pref.theme`（`auto`/`light`/`dark`）、`pref.fontsize`（`sm`/`md`/`lg`/`xl`）。

# 第一部分：必需功能

## N1 断点续做（练习草稿恢复）

### 用户价值
组卷做到一半，因接电话、退出、APP 被杀、切到别的页面而丢失进度，是最高频的"做白工"场景。本功能让任何一次练习都能在下次打开时从断点继续。

### 现状
- `runPaper()`（`static/m/m.js` L1546）把进度放在内存变量：`answers[]`（L1557）、`cur`、`marked[]`（L1558）。
- 退出/切页后内存即释放，无任何持久化。
- 已提交的作答虽然通过 `/api/answer` 落库，但"这套卷还剩几题、做到哪、哪些标了记"无法还原。

### 功能点
1. 进入练习时创建一个**草稿**，包含：
   - 卷类型标题、题目 ID 列表 `ids`
   - 当前题号 `cur`
   - 每题状态：`{sel, correct, ms, marked}`（已答但未到统一结算的也保存）
   - 是否考场模式、倒计时截止时间 `deadline`、创建/更新时间
2. 做题过程中**节流自动保存**（每答一题、每翻一页、每 15 秒），不阻塞作答。
3. 正常交卷结算后**清除草稿**。
4. 下次进入「刷题」相关入口时：
   - 存在未完成草稿 → 顶部显示「继续上次：《标题》还剩 N 题」+「放弃」按钮。
   - 点继续 → 还原题目、已答状态、标记、倒计时（考场模式剩余时间按 deadline 重算，若已过点则直接走交卷）。
5. 同一时刻只保留**最近一份**普通练习草稿 + **最近一份**考场草稿（互不覆盖）。

### 技术实现

**存储选型**：草稿要在 APP（WebView）与浏览器都可用，且数据量小，**优先存后端一张轻表**，这样换前端入口也能读到；纯前端 localStorage 作为兜底。

**数据库（迁移 v11）**：在 `_migrate()` 追加：
```sql
CREATE TABLE IF NOT EXISTS paper_drafts (
    id INTEGER PRIMARY KEY,
    scope TEXT NOT NULL,          -- 'normal' / 'exam'
    title TEXT,
    ids_json TEXT NOT NULL,      -- 题目 id 列表 JSON
    state_json TEXT NOT NULL,    -- {cur, answers:[{sel,correct,ms,marked}], deadline, updated}
    updated_at REAL
);
```
> 注意：这是用户级状态。移动端需确认写入路径为个人库；若现有迁移在共享库执行，则该表通过移动端连接同样可写（与 `answers` 一致即可——实现时先确认 `answers` 在移动端落在哪个库，照搬）。

**db 层新增函数**（`app/db.py`）：
```python
def save_paper_draft(scope: str, title: str, ids: list[int], state: dict) -> None: ...
def load_paper_draft(scope: str = "") -> dict | None: ...
def clear_paper_draft(scope: str) -> None: ...
def list_unfinished_drafts() -> list[dict]: ...   # 首页/刷题页提示用，返回精简信息
```

**接口（桌面 main.py，移动端同步）**：
- `GET /api/paper-drafts` → `{items:[{scope,title,left,total,updated}]}`
- `POST /api/paper-draft/save` body `{scope,title,ids,state}`
- `POST /api/paper-draft/clear` body `{scope}`
- `GET /api/paper-draft/{scope}` → 完整草稿（继续时拉取）

移动端在 `goshor_server.py` 的 `do_GET` 增加 `/api/paper-drafts`、`/api/paper-draft/...` 分支；`do_POST` 增加 save/clear。

**前端（m.js / app.js）改造 runPaper**：
- 入口处：若 `opt.resumeScope` 给定，先 `GET /api/paper-draft/{scope}` 还原，再继续；否则新建草稿。
- 抽一个内部函数 `persist()`：把当前 `cur/answers/marked/deadline` 序列化，调用保存接口（用一个简单节流 + `safeTimeout`，避免每题都写）。
- 在「翻页、作答、标记」动作后调用 `persist()`。
- `summary()` 正常结算成功后调用 clear。
- 组件卸载/切页时（项目已有离开钩子）最后保存一次。
- 首页 `renderHome()`（L1102）并行请求中加入 `/api/paper-drafts`，有草稿则在顶部渲染续做卡片。

**草稿提示卡片示例（结构，样式沿用 .card）**：
```html
<div class="card draft-resume">
  <b>继续上次练习</b>
  <div class="muted">《2022年真题》已答 8/15 · 还剩 7 题</div>
  <div style="display:flex;gap:8px;margin-top:10px">
    <button class="btn btn-primary" id="draftGo">继续</button>
    <button class="btn" id="draftDrop">放弃这套</button>
  </div>
</div>
```

### 边界与异常
- 草稿里的题目已被「废弃」或导入差异导致部分 ID 不存在：还原时过滤缺失题并提示"有 N 题已不可用"，不能整卷失败。
- 草稿 JSON 解析失败：当作无草稿（删除脏草稿），不阻断正常使用。
- 倒计时考场草稿：`deadline < now` 时，继续即按"时间到"直接结算。
- 保存失败（服务异常）：静默降级 localStorage，不影响做题。

### 验收标准
1. 做一套 15 题，答到第 8 题后强杀 APP / 刷新浏览器 → 重开出现续做卡片，还原后题号、已选项、标记正确，且已答不重复计入。
2. 正常交卷后草稿被清除，不再提示。
3. 普通卷与考场卷草稿互不覆盖。
4. 新增测试：草稿保存/读取/清除往返；还原时缺失题被过滤；过期考场草稿直接结算。
5. `pytest tests -q` 全绿。

### 工作量：2~3 天

## N2 学习提醒（本地通知）

### 用户价值
有计划不执行等于没有。本地定时通知解决"今天忘了学"，是坚持类工具的必备能力。

### 现状
- 有番茄钟、学习计划（`study_plan`），但没有任何系统级提醒。
- 安卓已有 `GoshorNative` 桥（`MainActivity.java` L358），可直接扩展，无需新引框架。

### 功能点
1. 设置页新增「学习提醒」：
   - 开关 + 每日提醒时间（默认 20:00）。
   - 可选「按计划提醒」：当天计划未完成才提醒；完成则不打扰。
2. 到点发一条本地通知，点击通知打开 APP 首页（并定位到今日任务）。
3. 支持「考试临近提醒」：考前 7/3/1 天额外提醒。
4. 网页/PWA：用 Web `Notification API`，在已授权时提醒（PWA 可配合 Service Worker 展示）。
5. 未授权/不支持时，设置页明确说明并引导开启系统通知权限。

### 技术实现

**安卓（推荐 AlarmManager 精确提醒，简单可靠；不要一上来引 WorkManager 复杂链路）**：
- 在 `MainActivity` 新增通知渠道：
  ```java
  NotificationChannel ch = new NotificationChannel(
      "study", "学习提醒", NotificationManager.IMPORTANCE_HIGH);
  notificationManager.createNotificationChannel(ch);
  ```
- 用 `AlarmManager.setExactAndAllowWhileIdle` 设定每日触发；触发点用一个 `BroadcastReceiver`，在接收器里发通知并 `PendingIntent` 回到 MainActivity（可带 extra 定位今日任务）。每天触发后在接收器里重新排次日。
- 开机后需重新注册：加 `RECEIVE_BOOT_COMPLETED` 权限 + 一个 boot receiver，读取已保存的提醒设置后重排。
- Android 12+ 精确闹钟需 `SCHEDULE_EXACT_ALARM`/`USE_EXACT_ALARM` 权限；不可用则降级 `setAndAllowWhileIdle`（允许不精确）。
- 在 `NativeBridge` 增加方法（保持与现有方法同风格，必须在非 UI 线程安全）：
  - `scheduleReminder(String hhmm, boolean planOnly)`
  - `cancelReminder()`
  - 返回字符串状态（成功/缺权限），前端展示。

**网页/PWA**：
- 前端封装 `requestNotifyPermission()`；PWA 的 `static/sw.js` 监听 `push`/`notificationclick`（无服务器 push 时，可在应用打开期间用定时器提醒；纯网页无法在完全关闭后可靠定时，需向用户说明）。

**设置持久化**：提醒偏好属"用户设置"，放入 settings（`config.DEFAULTS` 增加 `reminder_on / reminder_time / reminder_plan_only`），这样安卓与网页都能通过 `/api/settings` 读取，安卓排程以它为准。

**前端设置页**（`static/m/m.js` renderSettings 及桌面）增加开关、时间选择与"按计划提醒"勾选；保存成功后调用 `GoshorNative.scheduleReminder`（APP 内）或申请通知权限（网页）。

### 边界与异常
- 未授予通知/精确闹钟权限：返回明确原因，功能可降级，不报错。
- APP 内（WebView）才调原生；浏览器模式隐藏或禁用原生排程按钮。
- 当天已完成计划 + planOnly=true：通知取消/不发。
- 时区与系统 12/24 小时制：用统一 `HH:mm`，显示层本地化。

### 验收标准
1. 设定 1 分钟后的提醒，到点收到通知，点击进入 APP 首页。
2. 关闭开关后不再收到；重启手机后提醒仍有效（boot 重排）。
3. planOnly 场景：当天计划完成则不发。
4. 无权限时设置页有明确引导，无崩溃。
5. 接口/设置读写加测试；通知权限分支在无原生环境下可跳过。
6. `pytest tests -q` 全绿。

### 工作量：2.5~3 天（含 boot receiver 与权限分支）

## N3 首页考试倒计时

### 用户价值
把"离考试还有几天"放在首页最显眼处，制造持续紧迫感，是成本最低、驱动力很强的功能。

### 现状
- 考试日期**没有持久化**：仅在生成计划时由 `PlanIn.exam_date`（`app/main.py` L583）临时传入 `planner.build_plan`（`planner.py` L69、L82）。
- 首页 `renderHome()` 读不到考试日期。

### 功能点
1. 在设置/计划页填写一次考试日期，**持久化到 settings**（`exam_date`，`YYYY-MM-DD`，可为空）。
2. 首页顶部横幅：「距 XX 考试还有 N 天」。
   - >30 天：常规墨色；8~30 天：靛蓝；1~7 天：朱砂高亮；考试当天：「今天考试，沉着应考」；过期：显示"考试已结束"并允许更新日期。
3. 倒计时旁可放一个「今日任务」入口（衔接学习计划）。
4. 保留 `planner` 原有逻辑；若 settings 已有 exam_date，生成计划页默认预填。

### 技术实现
- `app/config.py` DEFAULTS 增加 `"exam_date": ""`。
- `app/planner.py` `build_plan` 签名不变；调用处（`main.py` 约 L619）改为优先取传入值、否则取 settings 的 exam_date。
- 计划页前端（m.js 约 L989/L1049）把 exam_date 写入设置（或生成计划时同时保存）。
- 首页 `renderHome()` 已并行拉取，可直接从 `/api/settings` 取 exam_date（为避免多一次请求，可让 `/api/stats` 顺带返回 `exam_date` 与 `days_left`，推荐此法）：
  - 在 stats 聚合里计算 `days_left = (date.fromisoformat(exam_date) - today).days`。
- 倒计时横幅纯 HTML/CSS，按 `days_left` 区间加 class 改色（复用 cinnabar/indigo 变量），不引图表。

**横幅示例**：
```html
<div class="countdown cd-soon">
  <span class="cd-n">12</span>
  <div><b>天后考试</b><div class="muted">2026事业单位联考C类 · 今天先完成 3 项任务</div></div>
</div>
```

### 边界与异常
- 日期为空：不显示横幅（或显示"设置考试日期"）。
- 非法日期/解析失败：忽略，不影响首页。
- 跨年、时区：统一按本地日历日计算（`datetime.date.today()`）。

### 验收标准
1. 设置日期后首页即时显示，跨天天数自动 -1。
2. 各区间颜色正确；当天/过期文案正确。
3. 生成计划页能预填已保存日期。
4. 测试：stats 返回 days_left 的各区间；空日期不显示。
5. `pytest tests -q` 全绿。

### 工作量：0.5~1 天（强烈建议与 N2 排同一批，复用 exam_date）

## N4 字号与阅读偏好

### 用户价值
科技文献、资料分析长文在小屏上默认字号吃力；可调字号是基础无障碍与长文阅读刚需。

### 现状
设置 DEFAULTS（`config.py` L19-L25）没有字号项；全站字号分散写死。

### 功能点
1. 设置提供字号四档：小 / 标准 / 大 / 特大。
2. 通过一个根 CSS 变量统一缩放正文字号（不逐元素改）。
3. 记住选择，刷新/重启保持；可选"行高宽松"开关。
4. 不影响题目原始排版（图片、表格最小宽度可横向滚动，不被压坏）。

### 技术实现
- 在 `<html>` 根上设置 `data-fontsize="md|lg|xl|sm"`，CSS：
  ```css
  :root{ --base-font: 15px; }
  html[data-fontsize="sm"]{ --base-font: 13.5px; }
  html[data-fontsize="lg"]{ --base-font: 17px; }
  html[data-fontsize="xl"]{ --base-font: 19px; }
  body{ font-size: var(--base-font); }
  ```
  移动端在 `static/m/m.css` 同步定义对应变量（移动基线字号不同）。
- 用 `Pref.set("fontsize", v)` 存储；脚本最早执行时读取并设置 `document.documentElement.dataset.fontsize`，放在 `<head>` 内联一小段或入口最前面，避免刷新闪一下。
- 设置页加一组分段选择器；切换即时预览。

### 边界与异常
- 特大字号下布局允许纵向变长，但不能横向溢出（容器 `min-width:0`、长文 `overflow-wrap`、表格区横向滚动）。
- 题面自带的固定像素图不受影响。

### 验收标准
1. 四档切换即时生效并持久化；双端表现一致。
2. 特大档在 320px 宽下无横向滚动（表格/公式区除外，可滚动）。
3. 测试可用现有 SVG/前端静态校验同款方式断言根属性被设置（可选）。
4. `pytest tests -q` 全绿。

### 工作量：1 天

## N5 夜间模式（宣纸夜景）

### 用户价值
睡前、暗光环境刷题频繁，浅色刺眼；夜间模式护眼且更省电，是成熟应用标配。

### 现状
全站仅浅色（CSS 变量定义在 `static/styles.css` L2-L9），无主题切换。

### 功能点
1. 三种模式：跟随系统 / 浅色（书房纸墨）/ 夜间（宣纸夜景）。
2. 夜间用**暖灰墨底 + 米白文字**（不是纯黑纯白），保持纸墨气质；朱砂/靛蓝做亮度微调保证对比度。
3. 记住偏好；"跟随系统"监听 `matchMedia('(prefers-color-scheme: dark)')` 自动切。
4. 题面图片/图表在夜间加轻微压暗或保持，不刺眼。

### 技术实现
- 在 `<html>` 设 `data-theme="light|dark"`，CSS 用变量覆写：
  ```css
  html[data-theme="dark"]{
    --paper: #201d18;  --paper-2: #2a2620;
    --ink: #e9e2d3;    --ink-2: #b9b0a0;  --ink-3: #857c6c;
    --line: rgba(233,226,211,.14);
    /* cinnabar 调亮一档以保证暗底对比 */
  }
  ```
  关键：项目大量颜色都已走变量（见 styles.css 变量用法），覆写变量即可整体切换；对少数写死 `#fff` 的元素（如答题卡某些单元格）需改为变量，逐个替换。
- 桌面 `styles.css` 与移动 `m.css` 分别补一套暗底变量。
- 偏好 `Pref.set("theme", ...)`；跟随系统时监听 `matchMedia` change；初始化尽量前置防闪烁。
- 设置页加分段控件（跟随系统/浅色/夜间）。

### 边界与异常
- 对比度：暗底下正文与背景对比比需达到可读标准（重点检查 ink-3 灰字、禁用态）。
- WebView 对 `prefers-color-scheme` 支持以系统为准；不支持时默认浅色。
- 富文本题里写死的浅色背景内联样式可能不协调，属可接受，必要时加 `img/table` 滤镜兜底。

### 验收标准
1. 三种模式切换正确，跟随系统在系统深浅变化时自动切换。
2. 暗底无大面积刺眼白底、正文清晰；双端主要页面逐一查看。
3. 偏好持久化、刷新不闪烁。
4. `pytest tests -q` 全绿（主题为前端能力，至少保证构建/脚本无语法错误）。

## G1 单题用时分析

### 用户价值
`answers.ms` 已在采集但利用不足。用时是与正确率同等重要的指标——能发现"会做但太慢"的题，尤其贴合用户数量关系"正确率高但慢"的实际痛点。

### 功能点
1. 各模块：平均单题用时、中位数、超时（自定义阈值）题数。
2. 列出"耗时最长 Top10"题目，可点进去重做。
3. 统计"会做但超时"的题（correct=1 且 ms 超阈值），单独成一个练习清单。
4. 报告/周报新增"节奏"小结。

### 技术实现
- `app/db.py` 新增 `time_analysis()`：
  ```sql
  SELECT module, AVG(ms) avg_ms, COUNT(*) n,
         SUM(CASE WHEN correct=1 AND ms>? THEN 1 ELSE 0 END) slow_correct
  FROM answers JOIN documents ON documents.id=answers.doc_id
  GROUP BY module
  ```
  （阈值按模块给默认，如数量 90s、资料 60s、言语 45s，可在 speed/config 配置。）
- Top 慢题用 `ORDER BY ms DESC LIMIT 10`。
- 接口 `GET /api/time-analysis`；双端在统计/报告页展示，纯表格 + 内联条形（CSS 宽度即可）。
- 无作答时给空状态。

### 验收标准
- 数据与实际作答一致；慢而对的题能组成练习。
- 测试：聚合 SQL 用临时库预置作答验证 avg/分组/slow_correct。
- `pytest tests -q` 全绿。

### 工作量：1~1.5 天

### O1 实施说明（与本文档的差异 / 补充）

- **加密只用标准库，不引第三方密码库**：文档只说「生成派生密钥加密 zip」。
  手机端由 Chaquopy 打包，任何第三方加密库都要额外备 Android wheel，风险高，
  所以：PBKDF2-HMAC-SHA256(20 万次) 派生两把密钥；用 `hashlib.shake_256`（标准库
  里的 XOF）当 PRF 分块取密钥流做流式 XOR；`HMAC-SHA256` 做 **encrypt-then-MAC**。
  信封格式 `GSYNC1 | salt(16) | tag(32) | ciphertext`。口令错 / 被篡改 / 非本格式
  一律抛 `SyncError`，**绝不**把解出来的垃圾写进数据库。
- **口令落盘复用既有 DPAPI 机制**：把原来只加密 `deepseek_api_key` 的单字段逻辑
  泛化成 `_SECRET_FIELDS` 表（新增敏感项只需往表里加一行），WebDAV 密码与同步口令
  共用同一条「明文不落盘」通路；安卓无 DPAPI 时明文留在应用私有目录，读回一致。
- **WebDAV 只用六个标准动作**：`PROPFIND`（连接测试）/ `MKCOL`（逐级建目录）/
  `PUT` / `GET` / `HEAD`（取远端大小与 Last-Modified）/ `OPTIONS`（PROPFIND 被禁时的
  降级探测），全部走标准库 `urllib`，不引 `requests`。远端相对路径拒绝 `..`/`.`
  段（路径会拼进 URL，放行等于开了目录穿越）。
- **双端共用一份实现**：`app/sync_webdav.py` 是桌面与移动**唯一**的加密/客户端/
  配置视图来源（`encrypt_bytes` / `decrypt_bytes` / `public_config` / `remote_newer` /
  `file_stamp` / `build_zip`）。移动端 `goshor_server.py` 只做「导出包 → 加密 → PUT」
  与「GET → 解密 → 走既有整包还原」的编排，**不另写一套加解密**（`test_mobile_reuses_shared_sync_module`
  钉住了这一点）。
- **冲突判断用「版本戳 + 云端时间」双条件**：本机 `sync_local_stamp` 由
  `{mtime_ns}:{size}` 拼成（**主库与 `-wal` 一起算**，否则 WAL 里的新数据会被漏判成
  「没变」）；`remote_newer()` 比较云端 `Last-Modified`(GMT) 与本机上次同步时间(本地
  时区 ISO)。**两边都动过**才判冲突，需 `force` 二次确认，避免「一边没动也弹冲突」。
- **恢复绝不冲掉本机同步凭据**：云端包里的设置会覆盖本机设置（同账号同配置本属预期），
  但 DPAPI 密文**跨机器解不开**，覆盖后用户会「既连不上云、又丢了本地密钥」，
  所以在落盘前把 `sync_*` 与两个 `*_enc` 先留好再回填（`test_sync_down_keeps_local_sync_credentials`）。
- **上传包不含 DeepSeek Key**：`_mobile_backup_export(False)` —— 云端包只放学习数据，
  长期有效的第三方 API Key 不进任何可上传的包（与手动导出默认一致）。
- **【本次修复】客户端不再走环境代理**：`_OPENER = build_opener(ProxyHandler({}))`。
  此前用 `urlopen()` 会默认读取 `http_proxy / https_proxy / all_proxy`，于是**本机/内网
  地址也会被系统代理改写**：连 `127.0.0.1:1` 时拿回来的是代理的 502，错误文案从
  「连接失败」变成「HTTP 502」，`test_client_connection_refused_raises` 因此变红。
  WebDAV 只应连用户显式填写的地址，故显式置空代理表；确需经代理时把代理写进
  WebDAV 地址本身。
- **【本次修复】测试不再依赖网络环境**：原 `test_client_connection_refused_raises`
  把文案也钉死了，在带代理的机器上不稳。改为**只断言抛 `SyncError`**（真实网络用途），
  另加两条**不依赖网络**的用例钉住契约：`test_connection_error_maps_to_readable_message`
  （把底层 opener 桩成抛 `URLError` → 文案「连接 WebDAV 失败」）与
  `test_client_bypasses_environment_proxy`（断言 opener 里**没有**代理 handler，
  并用默认 opener 做对照）。
- **【本次修复】校正一条写反的断言**：`test_client_bypasses_environment_proxy` 原写成
  「opener 应携带 `ProxyHandler`（空代理表）」。实际上 `ProxyHandler({})` 在空表下
  **不会生成任何 `*_open` 方法**，`OpenerDirector.add_handler` 因此不把它登记进
  `.handlers`——**这正是「不走代理」生效的机制**（默认 ProxyHandler 也已被 `skip`）。
  断言已改为「我们的 opener 不含代理 handler + 默认 opener 在同环境下含代理 handler」
  的对照写法，既符合实现事实，也真正钉住了「忽略 `http_proxy`」这条需求。

### N4 实施说明（与本文档的差异 / 补充）

- **复用移动端既存的 U-7 三档，扩成四档并做旧值迁移**：移动端早有 `fontsize` 偏好，
  但键值是 `s/m/b`（小/标准/大字），且走的是 `body.bigfont/.smallfont` 两个类。
  若按文档另起一套 `data-fontsize`，会变成两套并行、互相打架。所以：
  1. 把 U-7 并入 N4，档案统一为 `sm|md|lg|xl`，`<html data-fontsize>` 一个来源；
  2. 老用户存的 `s/m/b` 经 `LEGACY = {s:sm, m:md, b:lg}` 映射（**大字映射到 lg 而非 md**，
     否则等于把老用户的选择偷偷降级）；内联防闪脚本里也做同一份映射。
- **只缩放正文，不缩放 UI**：文档给的是 `body { font-size: var(--base-font) }`。
  但桌面端侧边栏/导航/按钮/表格的字号是逐条写死的，直接改 body 基数会让 UI 跟着变形
  （侧栏会挤、表格会崩）。实际做法是引入 `--base-font`（正文基数）与 `--read-font`
  （题面/长文基数）两个变量，只有**长文与阅读区**跟随（`.stem / .sz-content / .option /
  .doc-header h2`），UI 保持原样。这样「特大档」是让**读的内容**变大，不是整页变大。
- **N4 的字号跟随规则放在样式表末尾**：这些选择器（`.stem`、`.sz-content` 等）
  在上面已有写死的默认值，同优先级下**后写的赢**，所以必须放在最后；
  同时把原来那几处写死值改成变量，语义更清楚。
- **行高宽松**是独立开关（`Pref('lhloose')` → `html[data-lineheight="loose"]`），
  只改 `--read-lh`，不改字号 —— 文档里它本来就是可选项。
- **横向溢出**：特大档下给长文加 `overflow-wrap: anywhere`，表格/`pre` 加
  `max-width:100%; overflow-x:auto`（可各自滚动，但页面整体不横滑）。
  E2E 直接断言 `scrollWidth - clientWidth <= 1`，实测 0px。
- **校验器与 N5 共用**：`tools/check_appearance.mjs` 一并覆盖 N4（四档 + 旧值迁移 +
  行高开关 + 分段控件），避免两套几乎相同的沙箱代码。

### N5 实施说明（与本文档的差异 / 补充）

- **主题偏好键用 `theme`，值 `auto|light|dark`**：文档只提了 `data-theme="light|dark"`。
  但「跟随系统」是单独一种模式，不能塌缩成 light/dark（否则用户选了跟随系统后、
  系统一变就丢偏好）。所以偏好存三态、`<html>` 上落**解析后的** light/dark，
  `resolve(pref, sys)` 是纯函数、可测。
- **防闪烁做了两处**：`<head>` 里一段内联脚本先于 `<body>` 应用（这才是真正防闪的），
  `app.js/m.js` 的 `Theme.init()` 再跑一次兜底 + 订阅 `matchMedia` change。
  内联脚本与共享块逻辑等价但**不共用代码**（内联必须先于外部脚本，且要极小、不依赖 Pref）。
- **写死颜色收敛成语义变量**：原先散落的 `background:#fff`（桌面 28 处 / 移动 15 处）、
  `#f4f1e8`、`#eef2fb`、`#eef4ee` 等收敛为 `--surface / --surface-2 / --indigo-tint /
  --cinnabar-tint / --green-tint / --amber-tint / --indigo-line / --bamboo-ink / --green-ink`。
  夜间块只覆写变量，不逐元素改 —— 文档说的「逐页核对」实际就是这一步。
  验收里「无大面积刺眼白底」由 `test_no_hardcoded_white_background_left` 钉住。
- **顺带修掉移动端一个真实缺陷**：`m.css` 的 `.arg-*`（论证评价）与 `.iv-clock` 用了
  `var(--bamboo)`（7 处）、`var(--mono)`（1 处），但 `:root` 里**从未定义** ——
  这些声明一直整条失效、配色回落到继承值。N5 补齐了这两个变量。
- **移动端字号沿用既存的 U-7 三档**：移动端本就有 `fontsize` 偏好（`s/m/b`，走
  `body.bigfont/.smallfont`）。N4 若按文档另起 `data-fontsize` 会出现两套并行、互相打架，
  所以 N4 只补桌面端，并复用同一套 `.type-check` 分段控件样式（见 N4 实施说明）。
- **`color-scheme`**：夜间块设 `color-scheme: dark`，否则滚动条、日期选择器、
  输入光标这些**原生控件**仍是亮色，在暗底上很跳。
- **校验器用 computed style 断言而非只看属性**：E2E 里断言
  `getComputedStyle(document.body).backgroundColor === "rgb(32, 29, 24)"`。
  只断言 `dataset.theme === "dark"` 的话，「JS 设了属性但 CSS 变量没覆写/被覆盖」
  这类 bug 照样能溜过去 —— 那恰恰是最典型的「换了但没完全换」。

### 批次4 实施说明（G1/G2/G6，与本文档的差异 / 补充）

- **G1 超时阈值按模块显式给，其余由建议用时推导**：文档只点了数量 90s / 资料 60s /
  言语 45s 三个模块。实现里 `SLOW_SEC_DEFAULT` 显式列这三个（外加「言语理解」简称），
  其余模块用 `SUGGEST_SEC[module] * 1.5` 兜底、未知模块 60s —— 保证**任何**模块都有
  阈值（否则该模块永远算不出「超时」，静默漏统计）。「超时」判定是**严格大于**
  （`ms > 阈值*1000`），恰好等于阈值不算，测试里钉死了这条边界。
- **`ms <= 0` 的历史脏数据一律不计入**：均时/中位数/超时/Top 榜都只在 `ms > 0` 的
  行上算。否则一条 `ms=0` 的旧作答会把「中位数」直接拉到 0，节奏分析全废。
- **G1 不只是新页面**：`weekly_report()` 顺带算了 `pace = {n, slow_correct}`，
  周报卡片显示「会做但超时 N 题」并链到用时分析页；建议列表里也会多一条节奏提示
  （≥3 题才提示，避免噪声）。
- **G2 双目标取 min，而不是各算各的**：文档说「题量和/或专注分钟」。两项都设时，
  必须**两项都达标**才算完成，所以进度环的比例取 `min(题量完成度, 专注完成度)`；
  单项未设（=0）时该项按 100% 计，不拖后腿。若取 max，就会出现「题量刷满即当达标」
  的假完成。
- **G2 目标存在 settings，进度算在 db**：目标值随设置走（`daily_goal_questions` /
  `daily_goal_minutes`），API 层读出来后**作为参数传给** `stats_overview(goal_q, goal_m)`
  —— db 模块不反向 import config。`/api/stats` 顺带返回 `goal`，首页一次请求拿到
  环所需的全部数据，不新增接口。
- **G2 「0」是合法值**：0 表示「该项不设目标」。`normalize_goal` 不能用 `if not value`
  过滤，否则用户永远关不掉目标。两项目标全 0 → `enabled=False`，首页**不渲染**进度环
  （占位空白很丑）。
- **G2 连续达标天数与「连续学习天数」同口径**：今天还没达标**不算断**（当天没做题
  时 streak 会跳过今天再往前数）。streak 只在 `enabled` 时有意义。
- **G6 纯前端、单键、去重置顶**：`Pref('searchhist')` 存字符串数组，最多 20 条，
  新的置顶、旧的挤出；「仅有结果」才记录（`res.total > 0 && q`），空关键词不记。
  `list()` 对脏值（非数组 / 混入非字符串）做容错，避免一次脏写把历史整块卡死。
- **G6 双端共享块**：与 N5/N4 同一套「逐字节一致」纪律（校验器抽块比对），
  搜索页把 `${SearchHistory.html()}` 挂在筛选行下方，点标签回填输入框 + 重新检索，
  「清空」直接移除整块 DOM（不重渲染整页，保住输入焦点）。

### N1 实施说明（与本文档的差异 / 补充）

- **表结构照文档，但 `scope` 加了 `UNIQUE`**：文档给的 DDL 只有 `scope TEXT NOT NULL`。
  可「同一时刻只保留最近一份普通草稿 + 最近一份考场草稿」这个语义，靠应用层
  「先删再插」在并发下会留孤儿行；加 `UNIQUE(scope)` 后用 `INSERT OR REPLACE`
  天然覆盖，也不需要先查一次。实测覆盖行为由
  `tests/test_paper_draft.py::test_draft_same_scope_overwrites` 钉住。
- **落库在个人库**：`paper_drafts` 与 `answers` 同库（手机端是 `users/data_<uid>.db`），
  所以移动端可写、多账号天然隔离。已加 `test_draft_table_is_writable_on_mobile` 与
  `test_draft_isolated_per_user` 两条回归。
- **`ids` 用宽松 `list` 而不是 `list[int]`**：移动端那侧是裸 `http.server`、没有模型校验，
  如果桌面端用 `list[int]`，脏 id 会变成「桌面 422 / 手机静默过滤」的双端行为不一致。
  统一改成宽松类型，过滤收口在 `db._as_int_list()`（脏元素丢弃，不整份失败）。
- **`state` 里 `correct` 只在「已判分」时写入**：考场模式交卷前 `answers[i].correct`
  是 `undefined`，如果序列化时写成 `false`，还原后会被当成「已判过且答错」——
  选项被置灰、解析框直接弹出来。所以 `draftStateOf()` 用 `'correct' in item` 区分，
  `draftItemToAnswer()` 对应还原。这条由校验器里
  「考场模式未判分的题**不得**写 correct」钉住。
- **前端共享块自带一套定时器登记**：文档要求「定时器走 `safeTimeout/safeInterval` 并登记」，
  但桌面端 `app.js` 此前**根本没有**这两个函数（只有 m.js 有），而双端块要求逐字节一致。
  于是块内自带 `draftSetTimeout/draftSetInterval/draftClearTimers`，并在两端的 `route()`
  里各调一次 `draftClearTimers()`。
- **保存策略：前缘节流 + 尾随补写 + 15s 心跳 + 离开强制落盘 + pagehide beacon**，五层兜底：
  1. 前缘节流（`MIN_GAP=2500ms`）——正常答题时每次都写，连点时最多 2.5s 一次；
  2. **尾随补写**——窗口内被节流掉的那次，在窗口结束时刻自动补写一次。
     没有它的话，最后一次操作要等到 15 秒心跳才落盘（E2E 里就是靠这条才拿到
     「答完第 2 题立刻查服务端已更新」的确定行为）；
  3. 15s 心跳——兜住「尾随定时器被清掉 / 长时间停留」的脏数据（应对「答完就强杀 APP」）；
  4. `DraftPaper.leave()`——`exitRun()` / `route()` 里强制落盘（切页/返回键）；
     并**解除本次运行**（scope 置空）——否则下一次 `begin()` 的 `flush()` 会拿着旧
     scope/旧 state 把刚被「放弃」或已交卷的草稿又写回服务端（E2E 真抓到过这个 bug）；
  5. `pagehide` + `navigator.sendBeacon`——刷新/关页面时同步发出，不依赖 JS 继续跑。
- **少于 3 题不建草稿**：错题解析、收藏题、复习重做这些入口是单题流，
  建草稿既没意义、还会把真正的多题练习草稿覆盖掉。`DraftPaper.MIN_Q = 3`，
  另留 `opt.draft === false` 供以后显式关闭。
- **桌面端「继续」要绕一层**：桌面做题是内嵌在 `#/paper` 页的 `#paperBody` 里（不改 hash），
  所以 `draftResume()` 只能先记 `PENDING_RESUME` 再跳 `#/paper`，由 `renderPaper()`
  消费后调 `runPaper`；并且该判断必须放在「`#/paper/adaptive` 自动组卷」**之前**，
  否则从首页推荐位进来会把续做抢走。
- **过期考场草稿直接结算**：`deadline < now` 时 `autoSettle = true`，
  跳过「还有 N 题未作答，确定交卷？」的二次确认（文档原文「直接走交卷」）。
- **还原时已判题要能看出对错**：移动端原来 `show()` 对非考场模式的选项一律渲染成
  未作答样式（`judge()` 里有 `if (answers[cur]) return;`，看起来像没答过）。
  改成按 `a.correct !== undefined` 声明式渲染 `disabled/correct/wrong` 并补解析框
  （抽出 `renderAna()` 与正常作答共用，避免两处文案漂移）。
- **退出文案跟着改**：有草稿时桌面端 `#quitPaper` 的确认文案从「退出将丢失本卷作答进度」
  改成「退出后本卷进度已保存，可在首页「继续上次」找回」——否则用户不敢退。
- **顺带**：桌面端 `styles.css` 没有 `.card`，续做卡片在桌面会是裸文本，
  故两端各补一条 `.draft-resume` 样式（桌面按 `.panel` 风格给全，移动端只加朱砂左条）。
- **校验器自带虚拟时钟**：`tools/check_paper_draft.mjs` 用「可推进的假时钟 + 假定时器」
  驱动节流与 15s 心跳，不需要真的等 15 秒，也不会像 N2 那样把 Node 事件循环挂住。
- **桌面 E2E 的一个坑**：`runPaper()` 是**内嵌渲染**（把题面塞进 `#view`），并不改 hash。
  所以「切页触发 `route()` 强制落盘」这一步**不能**写成 `location.hash = '#/settings'`
  （hash 本来就是 `#/settings`，赋同值不触发 `hashchange`，`route()` 不跑、草稿不落）。
  必须切到一个**不同**的真实路由（测试里用 `#/marks`，移动 server 有 `/api/marks`），
  验证完再切回 `#/settings`。另：桌面段在切页前答了 Q1+Q2，草稿 `cur=1`，
  续做应还原到**第 2 题**（别照抄移动段的「第 1 题」）。

### 顺带修复：切页竞态（非 N3 引入，但会污染回归信号）

`scripts/e2e_mobile.py` 全路由遍历会随机报「某个路由 JS 错误」，真凶是移动端复习 / 卡片页的

### N2 实施说明（与本文档的差异 / 补充）

- **原生落地在独立类**，没有塞进 `MainActivity`（文档原文是「在 MainActivity 新增通知渠道」）：
  `ReminderScheduler.java`（排程 + 渠道 + 通知 + 时间计算，全静态方法）、

- **NativeBridge 方法比文档多 6 个**：除 `scheduleReminder/cancelReminder` 外，还加了
  `reminderStatus()`（设置页回显）、`syncPlanState(day,done,total)`、

  首页/计划页把「今日计划完成度」写进 SharedPreferences（`syncPlanState`），
  接收器据此决定要不要打扰——纯离线、不依赖网络，也不需要跨进程读库。
- **`scheduleReminder` 多一个 `examDate` 入参**：考前 7/3/1 天提醒要排程，原生必须知道考试日期；
  它同时落进 SharedPreferences，供 `BootReceiver` 重排。
- **每日闹钟不用 `setRepeating`**：Doze 下会漂移甚至丢触发，改为「每次触发后在接收器里重排次日」
  （`rescheduleDailyOnly`），长期更可靠。考前提醒是一次性闹钟，固定 10:00，与每日提醒错开。
- **`SCHEDULE_EXACT_ALARM` 拿不到就降级**：`canScheduleExactAlarms()` 为假时用

- **时间归一化两端同口径**：`config.normalize_time_hhmm()`（Python）与
  `ReminderScheduler.normalize()`（Java）都接受 `9:05` 与 `09:05` 并补齐成 `09:05`。

### 顺带修复：静态校验沙箱被常驻定时器挂住

`tools/check_svg_fit.mjs` 把真实前端脚本跑在 `vm` 沙箱里做 SVG 几何校验，沙箱里传的是
**Node 真实的 `setInterval`**。N2 在脚本尾部会起一个 60s 常驻轮询（`ReminderWeb.start()`），
于是 Node 事件循环永不退出，`tests/test_svg_fit.py` 从「秒级通过」变成「卡到 180s 超时」。

修法：该沙箱把 `setInterval/clearInterval` 桩成不占用事件循环的空实现（几何校验与定时器无关）。
回归用例：`tests/test_study_reminder.py::test_static_sandboxes_stub_setinterval`。
**教训**：任何「把真实前端脚本塞进 vm 跑」的静态校验，都要先想清楚脚本里的常驻定时器。

  两端都按普通文本渲染——这是**一致**的行为，不是缺陷。将来若要真支持引用，必须两端
  同时改，并回来把 `check_md_parity.mjs` 里的 C3 断言改成 `quote`。

### 顺带修复：桌面设置页勾选项错乱 + N4 字号四档跨度不足

用户实测反馈「字体大小变化不够明显，设置页面有些地方是乱的」。两处根因都不是文档设计
问题，而是实现细节：

- **勾选项错乱**：`.field input { width: 100% }` 把复选框也撑满整行——复选框变成居中
  孤零零的小方块、标签被挤到下一行。修法：选择器收紧为
  `.field input:not([type="checkbox"]):not([type="radio"])`，并新增 `.field label.cb`
  统一样式（复选框固定 16px、`flex: none`、`accent-color: var(--cinnabar)`），
  双选项行改用 `.field .cb-group`。
- **面板字段贴在一起**：外观 / 多设备同步 / 题库导出 PDF 三个面板不走 `.settings-form`
  （没有 `gap`），字段全部粘在一起。补 `.panel > .field { margin-bottom: 14px }`。
- **首个面板无标题**：字段揉成一坨且看不出分组，拆成「题库与 AI 接口」「学习与提醒」
  两个带标题面板，`rise-*` 入场序号顺延。
- **字号四档跨度不足**：文档只规定「四档」，没定跨度，原实现相邻两档只差 1px，
  切换肉眼几乎无感。现改为 `sm 12.5 / md 14.5(默认) / lg 16.5 / xl 19`（桌面 +52%、
  移动 +69%），只缩放正文变量 `--base-font` / `--read-font`，UI 尺寸不受影响。

## 1. 目的与边界

### 1.1 要解决的问题

原始资料是 68 份 PDF、混合了讲义、刷题课件与思维导图，直接搬运会出现三类问题：同一考点在多个文件重复出现、题目与知识点混在一起、分类边界模糊导致用户找不到。本规范用「三层结构 + 唯一归属 + 字数与条数硬约束」把扩展变成可核对的工序。

| 目标 | 判定方式 |
|---|---|
| 结构不乱 | 任意考点只出现在一个「模块 → 分类」路径下，分类数 4—9 个 |
| 内容够细 | 单考点正文 300—600 字（政治理论 600—900 字），配 3—5 条易错提示 |
| 配套可练 | 政治理论每点 1—4 道、资料/数量/判断/言语每点 1—3 道单选题（4 选项、答案 A—D、解析非空），题干常显、答案折叠 |
| 覆盖可查 | 每份源文件的章节都能在 §4、§5 的映射表中找到去处或标为缺口 |
| 格式可测 | `pytest tests/test_xingce_notes.py` 与浏览器自查同时通过 |

**不做**：

- 不改题库、不改判分逻辑、不重新打包 APK。
- 不把申论四份资料并入行测（申论归 `docs/03-开发/2026-10-26-申论评分接入ShenlunSkill方案.md` 的链路）。

## 2. 三层结构规范

### 2.1 层级与字段

「行测」是一个大模块，下面固定三层，层数不再增加，避免第四层目录。

| 层级 | 字段 | 约束 |
|---|---|---|
| 第一层 模块 | `key` / `name` / `icon` / `desc` | 固定六个；数组首项须为「资料分析」（测试硬约束） |
| 第二层 分类 | `key` / `name` / `desc` / `count` | 名称 4—10 字；`desc` 用「 · 」连接 3—6 个关键词 |
| 第三层 考点 | `title` / `body` / `tips` / `section` / `quizzes` | `section` 必须等于所属分类 `key`，不能为空；`quizzes` 为题目数组，政治理论 1—4 题、资料/数量/判断/言语 1—3 题，常识判断暂不配题 |

排序规则：模块按考纲顺序；分类按教材章节顺序（原理 → 制度 → 应用）；考点按知识递进，不按字母、不按重要度。

### 2.2 分类规则

分类是「用户找得到」的关键，按下列四条切分。

| 规则 | 说明 | 反例 |
|---|---|---|
| 单一维度 | 同一分类只用一个切分维度（学科、制度或题型） | 把「宪法」与「民法典」合成「法律一」 |
| 4—9 个 | 少于 4 个说明没切开，多于 9 个说明切碎 | 常识切出 15 个分类 |
| 单类 1—9 条 | 超过 9 条继续下切；只剩 1 条时确认它是否该并入相邻类 | 法律类塞进 20 条 |
| 名称可检索 | 用户能凭名称猜到内容，不用「其他」「综合」 | 「其他常识」 |

### 2.3 考点规则

| 项 | 规定 |
|---|---|
| 一个考点 | 只讲一个可考结论簇（一个制度、一条规律、一组数字） |
| 标题 | 不超过 20 字，不含「1.」「（一）」等序号；同组内唯一 |
| 正文 | 300—600 字（政治理论 600—900 字）；只写考场要用的结论，不复述教材推导，也不靠流水句凑字数 |
| 题目 | 政治理论每点 1—4 道，资料分析 / 数量关系 / 判断推理 / 言语理解每点 1—3 道单选：4 个选项、答案 A—D、解析说明每个错项错在哪；题干与选项常显，答案默认折叠 |
| 提示 | 3—5 条，每条必须是「易混点 / 易错项 / 数字陷阱」，不写感想 |
| 来源 | 不写文件名、不写页码；出处只在本文件 §4、§5 的映射表登记 |
| OCR | 禁止残句、错字、页眉页脚（如「不辜负每次相遇」）；发现即视为未完成 |

示例（合格写法，正文只保留结论与对比）：

```text
标题：古代选官与赋税制度
正文：
- 选官：世卿世禄 → 察举征辟 → 九品中正 → 科举（隋炀帝设进士科）→ 1905 年废除
- 赋税：初税亩 → 租庸调 / 两税法 → 一条鞭法 → 摊丁入亩
提示：科举「始隋、完唐、废清末」；两税法按资产征税；一条鞭法折银、摊丁入亩废人头税
```

### 2.4 格式契约

以下四条由 [test_xingce_notes.py](../../tests/test_xingce_notes.py) 强制校验，写作时先按此约束，避免返工。

| 约束 | 具体要求 |
|---|---|
| 列表 | 只用 `- ` 无序列表；正文不得出现 `1. `、`1、` 这类有序标记 |
| 标题 | 正文内不出现 `###` 或任何 Markdown 标题 |
| 版本 | `NOTES["version"]` 恒为 1；模块顺序首项为「资料分析」 |
| 唯一性 | 同一模块内考点标题不得重复；`TITLES` / `ROUTES` 保留「行测速查」 |

### 2.5 归属与去重

扩展时最容易乱的两件事，按固定优先级裁决，不逐案讨论。

| 情形 | 裁决 |
|---|---|
| 同一知识点跨学科（如「乡村振兴」既是政治又是经济） | 归原理/政策所在学科，另一侧不重复建点，必要时在提示里一句带过 |
| 同一知识点跨模块（如「党史」在文史资料里也出现） | 归政治理论，文史侧不建点 |
| 同一考点在两个源文件出现 | 合并为一条，取信息更全的版本，另一版本只补差异 |
| 同一考点在旧版已存在 | 先比对再决定「删除旧的」或「扩写旧的」，不允许两条并存 |
| 同一方法在不同讲义叫法不同（如 415 份数法 / 假设分配、线段法 / 十字交叉、跟屁虫原理、份数思维） | 只建一个考点，把各讲义的叫法作为**别名**写进该考点正文，保证搜得到、不重复建点 |
| 纯题目、纯例题 | 不入考点；只有反复考的结论才提炼成考点 |

### 2.6 题目配套规范

政治理论 35 个考点配 1—4 道单选题（共 67 题），资料分析 17 点、数量关系 18 点、判断推理 19 点、言语理解 14 点各配 1—3 道（共 134 题），题目作为考点的 `quizzes` 数组随 `NOTES` 一起下发，双端用同一份数据渲染。

| 项 | 规定 |
|---|---|
| 字段 | 每题为 `q`（题干）、`options`（4 个选项，不带 A/B/C/D 前缀）、`answer`（A—D）、`explain`（解析）；整点为 `quizzes` 数组 |
| 题源 | 优先用源资料原题；OCR 打散无法确认时，按《排坑手册》的「正误判断 + 正确答案修正」整理——错项当干扰项、正确表述当答案，解析保留原书修正关键词。四模块的原题从 `知识点综合/<模块>/整理/*.md` 抽，题干与选项按原意重写，数值重新验算 |
| 覆盖 | 排坑手册每章均落到对应考点；手册未涉及的考点（五对范畴、毛泽东思想、中特理论体系、党史、新民主主义革命）保留原有题目。四模块的图形推理类题目一律出「规律 / 方法判断」的文字题，禁止依赖图片 |
| 干扰项 | 取自高频设错点（张冠李戴、数字错位、语序颠倒、主体替换、单位量级、公式分母用错），解析要逐项说明错在哪 |
| 交互 | 题干与选项常显，答案与解析默认折叠；多题时标注「题目 1 / N」，每题独立展开收起 |
| 搜索 | 除标题与正文外，任一题干也参与搜索匹配 |

## 7. 扩展工作流

每类扩展都走同一套五步，不允许跳步；跳步最容易产生重复与错位。

| 阶段 | 输入 | 动作 | 产物 | 门槛 |
|---|---|---|---|---|
| 1 抽样 | 该类对应的源文件 | 只读该章，不看全篇 | 章节要点草稿 | 草稿不含题目原文 |
| 2 归类 | 草稿 + 现有分类 | 按 §2.5 裁决归属 | 考点清单 | 每条只有一个分类 |
| 3 撰写 | 考点清单 | 按 §2.3 写标题、正文、提示 | 代码条目 | 正文 300—600 字 |
| 4 查重 | 同模块全部考点 | 标题与正文比对，合并重复 | 去重后的条目 | 同组标题唯一 |
| 5 校验 | 改动后的仓库 | 跑专项测试、全量测试、浏览器自查 | 验收记录 | 三项全绿 |

对应命令（工作目录 `D:\GOSHORE`）：

```powershell
python -m pytest tests/test_xingce_notes.py -q
python -m pytest tests -q
python scripts/e2e_mobile.py
```

浏览器自查：桌面端用真实服务打开 `#/xc-notes`，核对入口页 6 个大框按钮（两列三行）、点大框进入单模块页、顶部按钮常驻可切换、再点同一模块返回入口页、分类可折叠、搜索跨模块命中、展开考点后可见题干与 4 个选项、点「查看答案与解析」展开解析且再点收起、控制台无脚本报错；手机端核对 6 个模块按钮、点击跳转并高亮、分类折叠与「展开全部」、题目与答案折叠正常。

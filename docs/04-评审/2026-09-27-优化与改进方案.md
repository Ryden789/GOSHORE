## 方案一：E2E 回归脚本固化

**目标**：把手工探针验证变成一条命令的常设测试，发版前必跑，防回归。

| 项 | 内容 |
|---|---|
| 新增 | `scripts/e2e_mobile.py` |
| 修改 | `.trae/skills/goshor-regression/SKILL.md`（加入调用步骤） |

**实现要点**
1. 脚本在 PC 上直接启动 `goshor_server.py`（共享库用 `.tools/mobile_prep/goshor.db`，用户数据隔离在临时目录，跑完即删），接口与真机完全一致
2. Playwright 无头浏览器固定断言：
   - 全路由遍历，零 JS 错误
   - 每次跳转恰好一次入场动画，且动画开始时 DOM 已是目标页（防"闪两次"回归）
   - 做题流闭环：开门守卫 → 抽题 → 判分 → 跳过 → 结算数据正确
   - 登录/游客切换、备份导出接口冒烟
3. 全部 PASS 退出码 0；任一 FAIL 输出定位信息

**验证方式**：故意改坏一处动画调用 → 脚本报 FAIL；改回 → 全 PASS。

## 方案二：AI 双轨制（两种都保留）

**目标**：没 Key 开箱即用；有 Key 体验增强；切换无损。

### 轨道 A：自配 Key（增强模式）
- 设置页保留现有 Key 配置，新增图文引导「如何免费申请 DeepSeek Key」：分步说明、一键复制接口地址与模型名、"只保存在本机"说明
- 保存时自动发最小请求验证连通性，成功显示「✓ 已连通」

### 轨道 B：免 Key 降级（默认模式）
| 功能 | 降级实现 |
|---|---|
| 词语填空 | 随 APK 预置 200 道本地题入共享库（离线可用）；「AI 扩充题量」按钮仅配 Key 后显示 |
| AI 批改 | 无 Key 切「对照自评」：参考答案 + 按维度勾选的评分表（沿用现有 rubric），自评分照样进统计 |
| 入口提示 | 两个页面顶部一行小字："配置 DeepSeek Key 可解锁 AI 命题/批改 →"，点击跳设置页 |

**改动文件**：`goshor_server.py`（词填接口无 Key 走本地题）、`m.js`（设置引导 + 降级分支）、`build_mobile_assets.py`（预置题入库）

**验证**：无 Key 新装 App，词填能做、批改能自评；配 Key 后同页自动切 AI 模式。

## 方案三：数据保全（解决"卸载账号就没了"）

**目标**：卸载前提醒、备份可得、恢复可靠。

1. **备份引导弹窗**：累计答题 ≥50 或首次使用满 7 天（先到为准），首页弹一次「备份学习数据」卡，按钮直接导出；关闭后 30 天内不再弹
2. **备份即分享**：导出按钮改走系统分享（Android Sharesheet），可直接发微信/存网盘；`MainActivity.java` 加 `shareFile` 桥
3. **恢复流程加固**：备份 zip 写入 `accounts.db` + 全部 `data_*.db`，恢复时整包还原——重装后**无需重新注册同名账号**，账号密码原样回来
4. 登录页加「从备份恢复」入口

**改动文件**：`goshor_server.py`（备份范围扩大）、`m.js`（弹窗 + 登录页入口）、`MainActivity.java`（分享桥）

**验证**：模拟器演练完整链路——答题 → 备份 → 卸载 → 重装 → 恢复 → 账号直接登录、记录全在。

## 方案四：题库热更新包

**目标**：不重装 APK 即可更新题目（尤其时政）。

### 原理
题库（`goshor.db`，只读共享库）与个人数据（`users/data_<uid>.db`）物理分离，个人记录只存 doc_id 引用题库，因此可整体替换题库文件而不动个人数据。

### 更新包格式
```
goshor-update-v3.zip
├── manifest.json     ← { "version": 3, "docs": 15234, "date": "2026-10-01" }
├── goshor.db         ← 新题库（剥离个人表 + VACUUM）
└── img/              ← 新增题目引用的公式图（仅增量）
```

### 制包端（电脑）
1. 现有桌面端流程把新题导入 `data/goshor.db`
2. `build_mobile_assets.py --pack-update`：剥离个人表 → VACUUM → 收集新增图片 → 出 zip
3. 硬性校验：新库必须包含旧库全部 doc_id（**只增不删**，否则个人库错题/收藏成死链；要下线题目标记"已废弃"而非删除）

### 手机端（用户 3 步）
1. 下载 zip 到手机（微信"用其他应用打开"亦可）
2. App → 导入 → 题库更新 → 选 zip
3. 提示"更新成功，重启生效" → 重启

内部流程：校验版本 > 当前 → 校验新库可打开且题数正常 → 旧库改名 `.bak` 留后路 → 写入新库 + 解压图片 → 重启加载新库；新库损坏自动回滚 `.bak`。

### 分发（两种都做）
- **在线检查**：更新包传 GitHub Releases，设置页显示当前题库版本 +「检查更新」（便利）
- **手动 zip**：群文件/线下传文件，App 内手动选择（离线兜底）

**验证**：旧版 App 装入含新题的更新包，重启后新题可搜可做，个人数据不动。

## 方案五：低配机实测（先测量再决定）

1. 建 2GB RAM 低配 AVD（或旧手机），测三项：冷启动到可交互、组卷查询耗时、首页统计耗时
2. 达标线：冷启动 <5s、单次查询 <500ms。达标只记录数据不改代码
3. 不达标时的预案（按测量结果选用）：
   - SQL：documents 的 module/考点字段确认走索引；stats_overview 多次 COUNT 合并为一次条件聚合
   - 前端：题目图片 `loading="lazy"`；错题/历史长列表分页
   - 包体：206MB 图片转 WebP 预计省 40%+（测量后值得才做）

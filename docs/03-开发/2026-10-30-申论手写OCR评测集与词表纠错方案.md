## 1. 目标与边界

### 1.1 要做什么

| 编号 | 目标 | 判定方式 |
|---|---|---|
| G1 | 建立可复现的手写 OCR 评测集，换方案时有客观依据 | 同一评测集两次运行，字准确率差异 = 0 |
| G2 | 量化各候选引擎在本人的字迹上的准确率 | 输出 CER / 字准确率 / 行准确率 / 混淆字对 Top20 |
| G3 | 建立申论领域词表，对识别结果产出**可审计**的纠错建议 | 每条纠错含「原文 / 建议 / 规则 / 依据 / 位置」，无静默替换 |

### 1.2 明确不做什么（防止范围蔓延）

| 不做 | 理由 |
|---|---|
| 不做模型微调 | 单人笔迹数据量不足，过拟合书写者；收益低于词表后处理 |
| 不做自动改字（静默替换） | 误替换会被评阅判成「作答失误」，污染 `wrong_reasons` 归因数据 |
| 不做通用 OCR（表格/公式/图形） | 申论正文为横排中文段落，无需结构识别 |
| 不做连笔的"完美识别" | 目标是降低重打成本，不是 100% 准确 |

## 3. 总体设计

两条独立流水线，互不耦合：

```
【评测流水线】
  手写卷面图 ──> 引擎A/引擎B ──> 识别文本 ──> 对比金标 ──> 指标报告
                                    │                     │
                                    └────> 混淆字对统计 <──┘

【纠错流水线】
  识别文本 ──> 词表(glossary) ──> 候选纠错 ──> 人工确认 ──> 终稿
                  │                                    │
                  └── 每条改动可追溯"命中哪个词、依据哪条规则"
```

设计红线：**评测与纠错分开**。金标只用于度量，绝不进入纠错流程——否则等于用答案改答案，指标失真。

## 5. 模块详设

### 5.1 engine.py（引擎层）

```python
class OcrResult:            # 统一返回结构
    text:   str             # 按行拼接全文（行间 \n）
    lines:  list[str]       # 逐行文本
    scores: list[float]     # 每行置信度（引擎不提供填 0.0）
    engine: str             # "paddleocr:3.7.0" / "rapidocr:1.x"
    elapsed_ms: int

def recognize(image_path: str, engine: str = "paddle") -> OcrResult: ...
```

三种运行状态必须显式区分，**禁止静默降级**：

| 状态码 | 含义 | 上层行为 |
|---|---|---|
| OK | 正常返回 | 继续 |
| ENGINE_MISSING | 未安装该引擎 | 报错并提示安装命令，不自动换引擎 |
| INIT_FAILED | 模型加载失败（网络/权重缺失） | 返回失败原因文本，供留痕 |

> **待实测**：paddleocr 3.7.0 的调用入口与返回对象结构，须由 `probe_paddle.py` 确认后再固化。
> 不得凭 2.x 记忆写代码——这是本方案唯一强制的前置动作。

### 5.2 corrector.py（纠错层）

输入引擎文本，输出 `(corrected_text, changes, suspicious)`。

**四层规则，从严到宽，只建议不替换：**

| 层 | 规则 | 触发条件 | 置信度 |
|---|---|---|---|
| L1 精确命中 | 文本中已有的词表词逐条登记 | 精确匹配 | 高（仅登记） |
| L2 邻词修复 | 窗口片段不在词表，但与**首字相同**的词表词编辑距离 = 1 | 窗口长 3–6，首字相同 | 中 |
| L3 形近字局部修复 | 替换某形近字后片段变成词表词 | 须在 `confusable_zh.txt` 内 | 中 |
| L4 可疑标记 | 窗口不在词表且无候选，但置信度低 | 引擎 score < 阈值 | 低（仅标记） |

**changes 单条结构（缺项不允许输出）：**

```json
{"line": 3, "start": 12, "end": 17, "raw": "新质声产力",
 "suggest": "新质生产力", "rule": "L2", "basis": "词表命中：新质生产力",
 "confidence": 0.86}
```

**硬约束：**
1. 同一位置仅取最高分候选，**不连锁改写**（改完不再进第二轮）；
2. L2 要求首字相同——中文词表纠错最大的误伤来源，就是首字不同却被强行匹配；
3. 所有改动默认**不自动应用**，输出建议清单由人工确认。

### 5.3 evaluate.py（评测层）

指标定义（写死，避免口径漂移）：

| 指标 | 定义 |
|---|---|
| CER | 字符级 Levenshtein 距离 ÷ 金标字数（**标点计入，不豁免**） |
| 字准确率 | `1 − CER` |
| 行准确率 | `difflib.SequenceMatcher` 行级对齐后，完全相同行数 ÷ 金标行数 |
| 混淆字对 | 对齐后 `replace` 且两侧长度均为 1 的 (金标字, 识别字)，按频次降序取 Top20 |

产物：`logs/eval_<时间>.json`（机读）+ `.md`（人读，含逐样本明细与最差 5 例）。

## 6. 评测集规范

| 项 | 规定 |
|---|---|
| 规模 | ≥ 20 份，四类各 ≥ 5（工整 / 快速 / 涂改 / 弱光） |
| 单份 | 400–1000 字，与真实考场一致 |
| 采集 | 手机拍摄、自然光、正对、不裁切不加滤镜（保留真实噪声） |
| 命名 | `images/<split>/<id>.jpg`，`<id>` 形如 `e01` |
| 金标 | `labels/e01.txt`，逐行对应卷面行；标点照抄 |
| 划分 | 20 份**全部作为测试集**，不做训练用途 |
| 防泄漏 | 金标只被 `evaluate.py` 读取；`corrector.py` 不得引用 `labels/` |

**为什么强调「不做训练用途」**：训练过的样本上测准确率没有意义；这 20 份是标尺，用一次算一次。

## 7. 词表规范

| 项 | 规定 |
|---|---|
| 来源 | 以 `申论素材库_主题分类与使用场景.md` 的「规范表达」列为种子，人工筛选 |
| 初始规模 | 150–250 词（10 个高频主题 + 内蒙古区情） |
| 格式 | 一行一词，`#` 开头为注释，按主题分组 |
| 长度 | 仅收 ≥3 字（2 字词误伤率过高，L2 不用） |
| 维护 | 每次新增在 §10.3 记一条（日期 / 新增数 / 依据） |
| 版本 | 文件首行注释 `# version: v1 / date: yyyy-mm-dd / count: N` |

**收录原则**：只收**几乎不会出现在其他含义里**的政策术语（如「新质生产力」「放管服改革」）。**不收**常见双字词与成语——它们在任何语境下都可能合法出现，收进来只会制造误伤。

## 9. 验收标准

| 编号 | 验收项 | 通过线 |
|---|---|---|
| A1 | 评测可复现 | 同一评测集连续两次运行，字准确率差异 = 0 |
| A2 | 基线成立 | ≥1 个引擎在 20 份评测集上跑通，输出完整报告 |
| A3 | 纠错有增益 | 纠错后字准确率提升 ≥ 1.5 个百分点，且**误替换数 = 0** |
| A4 | 纠错可审计 | 每条 changes 六字段齐全，可人工复现判断依据 |
| A5 | 无泄漏 | `corrector.py` 代码与运行期均未读取 `labels/` |
| A6 | 可用性 | 单份卷面（1000 字）端到端（识别 + 纠错建议）≤ 30 秒 |

> A3 的「误替换数 = 0」比「提升幅度」更重要：**错的自动纠错比不纠错更危险**。

| 风险 | 影响 | 对策 |

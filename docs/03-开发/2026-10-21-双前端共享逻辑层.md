# 双前端共享逻辑层（P3）

> 目标：桌面端 `static/app.js` 与移动端 `static/m/m.js` 里那些**逐字节相同**的纯逻辑，不再各存一份；抽到 `static/shared/` 后两端加载同一文件，改一处即两端生效。

## 为什么做

拆库之前统计过一次重复量：仅「N5 主题 / N4 字号 / G2 每日目标 / G6 搜索历史 / G3 笔记 / G4 翻页 / N1 草稿 / N2 提醒」这一整段，两端就有 **796 行逐字节相同**的代码；再加上富文本净化（56 行）与 `settleExam`（27 行），重复接近 **900 行**。

重复的代价不是体积，而是**漂移**：过去每个功能都要在两端各改一次，靠 15 个 node 校验器断言「两端块逐字节一致」来兜底。校验器能发现漂移，但不能阻止有人只改一端；一旦发现，还得人工把改动抄到另一端。共享层把「靠测试发现」变成「结构上不可能不一致」。

## 目录与职责

```text
static/
├── shared/
│   ├── sanitize.js   # 富文本净化：SANITIZE_TAGS / SANITIZE_VOID / escText / sanitizeTag / sanitizeHtml
│   ├── settle.js     # 交卷统一判分：settleExam(docs, answers)
│   └── core.js       # 纯前端逻辑：Theme / FontSize / GoalRing / SearchHistory / NoteBox /
│                     #   SwipePaging / DraftPaper / ReminderWeb 及其辅助函数
├── app.js            # 桌面端 UI、路由、接口调用、渲染（保留）
└── m/m.js            # 移动端 UI、路由、接口调用、渲染（保留）
```

**留在各端、不共享**的：

- `Pref`（两端实现相同，但属于各端启动早期的基础设施，且 `check_appearance` 等校验器以各端 `Pref` 为沙箱输入）；
- `esc`（桌面端是函数、移动端是 `const`，签名不同）；
- `rawHtml`（桌面 `rawHtml(s) => sanitizeHtml(s)`；移动端是 `const rawHtml = s => sanitizeHtml(s)`）；
- `md()`：桌面端保留白名单标签渲染（要过 `sanitizeTag`），移动端仍整体转义 HTML——两端渲染策略本就不同；
- 所有 DOM 渲染、路由、`api()` 调用与页面级状态。

共享文件只放**不依赖具体 DOM 结构**的逻辑；`core.js` 内对 `document` / `window` / `Pref` / `api` 的引用都在函数体内惰性求值，加载顺序只要求「先 shared、后本端脚本」。

## 加载顺序

`static/index.html`：

```html
<script src="/shared/sanitize.js?v=20261029"></script>
<script src="/shared/settle.js?v=20261029"></script>
<script src="/shared/core.js?v=20261029"></script>
<script src="/app.js?v=20261029"></script>
```

`static/m/index.html` 同样顺序，最后一行换成 `/m/m.js?v=20261029`。

三个文件都是 **classic script**（不是 ES module），共享同一个全局词法环境，因此 `core.js` 里定义的 `Theme` / `DraftPaper` / `ReminderWeb` 等对本端脚本直接可见，不需要挂 `window` 或改调用点。`core.js` 末尾有唯一一个顶层副作用：

```js
window.addEventListener("pagehide", () => DraftPaper.beacon());
```

它原先在两端各写一次，现在只执行一次；`DraftPaper.beacon()` 内部会判断有没有进行中的草稿，没有则直接返回。

`sw.js` 的 `SHELL_ASSETS` 已加入三个 `/shared/*.js`，`VERSION` 升到 `goshore-20261029`，并与两个 `index.html` 的 `?v=20261029` 保持一致；不升版本会让旧 Service Worker 继续发旧脚本，出现「共享文件 404 / 旧 app.js 找旧函数」的错配。

## 校验器与测试怎么改

共享化之后，「两端逐字节一致」这条断言失去对象——两端已经没有可比的块了。处理原则：

1. **共享文件的唯一性**：`static/shared/*.js` 必须存在，且定义关键符号（`sanitizeTag` / `settleExam` / `DraftPaper` 等）。
2. **两端不再内联**：`app.js` / `m.js` 不得再出现 `function sanitizeTag(`、`const DraftPaper = {`、`function settleExam(` 等实现。
3. **页面真的加载了**：两个 `index.html` 都含 `/shared/xxx.js`，且位于本端脚本之前。
4. **行为断言照旧**：node 校验器仍把共享文件抽进假沙箱，真跑 Theme/FontSize/GoalRing/NoteBox/SwipePaging/DraftPaper/ReminderWeb/settleExam 的行为与篡改自检。

具体改动：

- `tools/check_appearance.mjs`：N5 主题块、N4 字号块改从 `shared/core.js` 抽取；`Pref` 仍按端注入；断言改为「两端源码不含 `/* N5 夜间模式`」「两端 html 在自身脚本前加载 `/shared/core.js`」。
- `tools/check_batch4.mjs` / `check_batch5.mjs`：G2 / G3/G4 块从 `shared/core.js` 抽取，静态接线仍检查各端（调用点留在 `app.js` / `m.js`）。
- `tools/check_paper_draft.mjs`：N1 块从 shared 抽取；「是否内联」改用 `const DraftPaper = {` 判断，不能再用 `/* N1 断点续做`——指针注释里也出现了这个词。
- `tools/check_reminder.mjs`：N2 块从 `shared/core.js` 抽到 `/* shared-core:end */`；两端只断言「加载了共享文件」。
- `tools/check_exam_daub.mjs`：只加载一份 `shared/settle.js`，输出改为「抽取到 1 份 settleExam」；双端仍断言 `summary()` 调用 `settleExam()`。
- `tools/check_xss_sanitize.mjs`：只构建一个共享净化器实例；C 段由「双端输出逐字节一致」改为「两端 html 加载 `/shared/sanitize.js`、两端不再内联常量与函数」；`md()` 仍从 `app.js` 抽白名单/`esc`/`stripWl`。
- `tools/check_md_parity.mjs`：`buildMd(src, kind, sharedSrc)`，桌面端只把 `SANITIZE_TAGS` / `SANITIZE_VOID` / `sanitizeTag` 的来源换成 shared，其余仍来自 `app.js`。
- `tools/check_svg_fit.mjs`：`vm` 沙箱先按页面顺序执行三个 shared 文件，再执行本端脚本（否则 `hydrateReminderPref` 未定义）。
- Python 侧：`tests/test_appearance.py`、`test_daily_goal.py`、`test_doc_notes.py`、`test_paper_draft.py`、`test_search_history.py`、`test_study_reminder.py`、`test_security_hardening.py`、`test_exam_daub.py` 同步改为「共享文件 + 两端加载 + 两端不内联」，不再比较已不存在的两份块。

`tests/test_check_content.py` 顺手修了一个环境相关缺陷：子进程 stdout 走管道时 Windows 默认用 locale 编码（cp936）输出中文，而用例按 UTF-8 解码，会把「严重问题 0 道」读成乱码；现在显式给子进程 `PYTHONUTF8=1`，在非 UTF-8 控制台也能稳定通过。

## 验证

```bash
# 15 个 node 校验器全绿
node tools/check_appearance.mjs   # 以及其余 14 个

# 全量 pytest
python -m pytest tests -q
```

本次结果：

- 15 个静态校验器全部 EXIT=0；
- `pytest` **915 passed**（P3 当次；比共享化前少 1 条：`test_both_ends_have_sanitizer` 从双端参数化改为共享文件单参数化，断言内容变多、用例数变少）。P4 合入后基线为 **928 passed**，安全加固后最终 **971 passed**，15 个 checker 全绿；
- `app.js` 7895 → **7033** 行，`m.js` 7459 → **6597** 行；新增 `shared/` 三个文件合计约 915 行，净减约 1800 行重复。

## 边界与后续

- 共享层目前是 **classic script + 全局符号**，不是模块系统。它适合当前「无构建、直接双击 HTML 也能跑」的约束；如果将来引入打包器，可以整体迁成 ES module，调用点命名不变。
- 共享文件里的函数仍直接读 `document.documentElement` / `localStorage` / `window.GoshorNative`，node 校验器通过假沙箱注入这些对象；新增共享逻辑时，保持「顶层无副作用、依赖在函数内取」这条约定，校验器才能继续真跑。
- P4 的内容抽检与规则校验器是**服务端/工具链**能力，不依赖本次共享层；但共享层让后续前端规则（如「题干 HTML 残留」的展示侧兜底）只需改一处。

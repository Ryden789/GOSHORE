# 2026-10-21 题库与个人数据分离（content.db + user.db）

> 配套代码：`app/db.py`（split 段）、`app/importer.py`、`app/main.py`（备份/同步）、`tools/migrate_split.py`
> 配套测试：`tests/test_split_db.py`（16 条）、`tests/test_storage_broken.py`（9 条）

## 一、为什么要拆

改造前，桌面端所有东西都躺在一个 `data/goshor.db` 里：23,491 篇题库、FTS 索引、
以及作答记录 / 错题 / 卡片 / 复习计划 / 设置副本。这个「一个文件装两种东西」的
结构，直接卡住了三件事：

| 症状 | 根因 |
|---|---|
| 导出备份要 142 MB / 8 秒 | 备份整库，其中 99% 是用户根本没改过的题库 |
| WebDAV 同步一次传 250 MB | 同上，同步的也是整库 |
| exe 不敢内置题库 | 内置就得连个人数据一起覆盖，升级会冲掉记录 |
| 题库没法整体替换 | 换题库 = 换整个库 = 连记录一起换 |

而手机端其实早就分开了：APK 里塞的是只读题库（`assets/payload.zip` → 272.5 MB），
个人数据写在自己的库文件里。**桌面端只是没走这条路。**

## 二、两种布局（程序自动识别，不需要配置）

| 布局 | 判定条件 | 读写方式 | 备份体积 |
|---|---|---|---|
| **split**（推荐） | `data/content.db` + `data/user.db` | 个人库为主库，`ATTACH content.db?mode=ro`，`documents`/`shizheng` 是 TEMP VIEW | **0.78 MB / 0.08 s** |
| legacy（老） | 只有 `data/goshor.db` | 单库直连，和改造前完全一致 | 142 MB / 8.2 s |

判定只在 `db.split_state()` 一家，规则是刻意简单的文件存在性检查——用户能自己
用资源管理器看懂、也就能自己修：

```
content + user            → split
只有 content，无 goshor.db → split（user.db 缺失=首次运行，自动建）
只有 content，却有 goshor  → broken（两套布局同时在，不猜）
只有 user                 → broken（个人数据在、题库没了，最危险）
都没有：有 goshor.db      → legacy
        有 .migrated      → broken（迁移过但新库丢了）
        都没有            → legacy（全新安装）
```

## 三、关键设计约束

1. **`documents` / `shizheng` 在个人库连接上是只读视图。** 写它们会报
   `cannot modify documents because it is a view`。这是有意的：题库只能经由
   `content_writer()` 写，避免「个人连接顺手改了题库」这种事故。
2. **个人覆盖层**：难度修正写 `doc_overrides`，时政测验答案写 `shizheng_quiz`，
   视图里用 `COALESCE(o.difficulty, d.difficulty)` 合并。所以「我个人觉得这题
   偏难」不会污染题库文件。
3. **`content_writer()` 只建 `SHARED_SCHEMA`**（3 张表），绝不把 22 张个人表
   建进题库文件——否则 content.db 就没法整包分发了。
4. **FTS 表必须 `FROM shared.docs_fts`**：写成 `shared.docs_fts MATCH` 会报
   `no such column`。另注：`docs_fts` 是普通 fts5 表（非 external-content），
   `INSERT INTO docs_fts(docs_fts) VALUES('rebuild')` 对它无效，迁移只能逐行复制。

## 四、迁移工具 `tools/migrate_split.py`

```bash
python tools/migrate_split.py --dry-run   # 只看会搬什么，不落盘
python tools/migrate_split.py             # 真迁移
```

安全设计：**绝不原地改源库**。

1. 用 SQLite 在线备份 API 把源库复制到**同目录**临时文件（跨卷 `os.replace`
   不是原子的，所以不放系统临时目录）；
2. 所有拆分工作都在副本上做；
3. 逐表校验行数 + `_meta.schema_version` 全过，才用 `os.replace` 落到正式文件名；
4. **最后**才把原库（含 `-wal`/`-shm`）改名成 `goshor.db.migrated` 保留，不删；
5. 任何一步失败：清临时文件、原库一个字节不动。

已存在 `content.db` / `user.db` / `.migrated` 时直接退出码 1，绝不覆盖。

> ⚠️ 跑迁移时**不要用 `| Select-Object -First N` 截断输出**。管道提前关闭会杀掉
> Python 进程，表现为「0.2 秒就结束、没落盘、留一个 `.split-migrate-*` 临时目录」。
> 已踩过一次：原库没坏（工具的设计兜住了），但白跑一轮。

### 实测（真实库，2026-10-21）

| 项 | 结果 |
|---|---|
| 源库 | `data/goshor.db` 430.55 MB / schema_version 12 |
| 耗时 | 42.67 s（副本迁移首轮 12.97 s，差异来自首次写 428 MB 的页缓存） |
| content.db | **428.39 MB** — documents 23,491 / docs_fts 23,538 / shizheng 7 |
| user.db | **1.81 MB** — 37 张个人表、2,927 行（与源库逐表一致） |
| 备份 | `goshor.db.migrated` 430.55 MB（与源库同尺寸） |

迁移后跑通：

- `python -m pytest -q` → **897 passed**
- `python scripts/e2e_mobile.py` → **33 路由 / 79 项断言全 PASS**（真库、真 split）
- `/api/health` → `{"ok": true, "app": "goshore", "storage": "split"}`
- `/api/backup/export` → **0.78 MB / 0.08 s**（改造前 142 MB / 8.18 s）

## 五、比设计更严的一道闸：`StorageBroken`

子代理的原始实现里有个隐患：split 判定要求两个文件都在，于是**用户误删
`content.db` 时会静默回落到 legacy** —— 而迁移后 `goshor.db` 已改名，legacy
分支会**新建一个空的 goshor.db**，用户打开软件看到「题库 0 道、进度全空」，
以为数据被清光了，其实个人数据好好地躺在 user.db 里。

我复现了这个场景（把 content.db 改名后 `connect()`），确认会凭空造出 4 KB 的空库。
改成：

- `split_state()` 明确区分 `split` / `legacy` / `broken`；
- `connect()` 遇到 `broken` 直接抛 `StorageBroken`，**不新建任何文件**；
- 文案是可照着做的：指名缺哪个文件、各多大，并给出两条退路
  （A 找回文件；B 退回单库模式）；
- `lifespan` 捕获它之后**仍然把服务起起来**——窗口能打开、页面能把原因显示给
  用户，比进程直接退出、窗口一闪而过好得多；各数据接口统一返回 503 + 说明；
- `/api/health` 暴露 `storage` 字段，排查「题库突然空了」时一眼看到真正原因。

## 六、已知遗留

1. **doc_id 错位**：导入旧版「整库备份」时题库表会被摘掉，但个人记录里的
   `doc_id` 仍指向旧题库。若新题库 id 变了，错题 / 卡片会错位。本轮没做 id
   重映射（超出存储拆分范围）。
2. **`_ensure_content_columns` 每次 `content_writer()` 都跑一次**幂等回填，
   大库首次有全表 UPDATE 扫描；实测可忽略，未做缓存。
3. **迁移落盘阶段的极端中断**：若放置新库成功、改名 `-wal` 失败，代码会回滚
   已放置的新库，但源库可能已被改名。同目录 rename 失败概率极低，未做跨步骤事务。

## 七、回滚方式

```powershell
cd D:\GOSHORE\data
Remove-Item content.db, user.db            # 丢掉新布局
Rename-Item goshor.db.migrated goshor.db   # 老单库回来
```

程序按 legacy 路径照常运行，一条记录都不会少。

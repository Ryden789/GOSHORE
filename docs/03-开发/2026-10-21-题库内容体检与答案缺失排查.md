# 2026-10-21 题库内容体检与「答案缺失」排查

> 配套代码：`tools/check_content.py`、`tests/test_check_content.py`
> 本文记录一次全量内容体检的口径、结果，以及查出的唯一一类真问题。

## 一、为什么要做这件事

题库不是手写的，是从 Obsidian 笔记批量解析入库的：题干、选项、正确答案、解析
全靠正则与启发式抽取（`app/parser.py` + `app/db.py` 的 `_upsert()`）。这类流程
**不会抛异常**——它只会静默产出坏数据：某道题的选项只剩两项、`correct` 全是
false、解析被截断成空串。

备考软件和其它软件不一样：答错一题，用户就再也不信它了。所以「有多少道题是坏的」
必须是一个能随时跑出来的数字，而不是等到用户投诉才发现。

## 二、工具与口径

```
python tools/check_content.py            # 自动找 data/content.db 或 data/goshor.db
python tools/check_content.py --strict   # 有严重问题时退出码 1（给 CI 用）
python tools/check_content.py --json out.json
```

判定分两档：

| 档位 | 含义 | 项目 |
|---|---|---|
| 严重 | 用户会直接看到坏题、或判分必然出错 | 选项数≠4、无正确选项、多正确选项、题干为空、qid 重复 |
| 提示 | 不影响判分，但值得抽查 | 无选项（判断题/主观题）、题干过短、解析过短、难度缺失、资料分析缺材料、选项文本全空 |

口径上有两处**刻意的例外**，都是踩过误报才定下来的：

1. **无选项不算坏题。** 正误判断题、主观题本来就只有题干。最初把它归为「选项
   字段不可解析」的严重项，一跑就把 1 道正常判断题报成坏题。
2. **题干长度阈值要分模块。** 判断推理·类比推理的题干天然极短（`太阳：东升西落`
   只有 7 个字）。用统一阈值 8 去卡，527 道好题全被误报成「题干为空」。现在
   「题干为空」只认 `len < 2`，另设「题干过短」提示项并排除判断推理。

## 三、全量结果（data/goshor.db，12,393 道真题）

| 项目 | 数量 | 占比 |
|---|---|---|
| 严重问题合计 | **11 道** | **0.09%** |
| 无正确选项 | 11 | 0.09% |
| 选项数异常 / 多正确选项 / 题干为空 / qid 重复 | 0 | 0 |
| 提示：无选项（判断题） | 1 | — |
| 提示：解析过短 | 2 | — |
| 提示：资料分析缺材料 | 2 | — |
| 提示：题干过短 / 难度缺失 / 选项文本全空 | 0 | — |

结论：题库整体是干净的。唯一的真问题是 **11 道题的选项里一个 `correct` 都没有**。

## 四、这 11 道题意味着什么

判分逻辑是 `"correct": o["label"] == item["answer"]`（`app/db.py:3270`）。当一道题
没有任何选项标了 `correct` 时，`answer` 落到空串，**用户无论选哪个都会被判错**——
而且他会以为是自己错了。这是最伤信任的一种 bug。

11 道全部集中在 `判断推理 / 逻辑判断`：

| 文件 | 解析里能恢复的答案 |
|---|---|
| 2051694 真假推理-矛盾关系（只有一真） | B |
| 2051696 分析推理-匹配排除（人物与行业对应，选非多选） | A |
| 2051700 真假推理-确定信息代入+唯一真话者身份绑定 | B |
| 2051704 分析推理-数量约束+假设反证列表排除 | A |
| 2051708 加强论证-补充论据（多选型支持题） | A |
| 2051710 加强论证-补充论据（多选题） | B |
| 2051716 削弱质疑-多选型（削弱论据+举反例削弱论点） | B |
| 2377318 翻译推理-假言与选言综合 | B |
| 2377321 削弱论证-多选削弱 | A |
| 2377340 翻译推理-真假话问题（矛盾关系+找其余） | B |
| 2377366 日常结论题（由此可以推出-双选） | A |

来源：这些题的 `options_raw` 里**没有** ✅ 标记（源笔记本身就漏标），但官方解析
里都有明确结论句，用四条正则（`答案(为|是|选) X` / `故选|应选|当选 X` /
`X 项(正确|当选|符合题意)` / `选择 X 项`）逐题抽取，11 道全部抽出**唯一**候选。
探针脚本见 `.tmp/probe_missing_answer.py`（不入库）。

## 五、修复策略（下一步）

1. **保守修复**：只对「正则抽出唯一候选」的题写回 `options[].correct`，默认
   `--dry-run`，输出改动清单；标题含「多选 / 双选」的单独列出人工确认，因为
   多选题理论上应有 2 个正确项，正则只找到 1 个可能只是解析里只强调了其中一个。
2. **兜底不改数据**：给「无正确选项」的题一个显式状态（答案缺失），作答后不参与
   判分、不计入正确率，界面标注「本题答案待补」。宁可不算，也不要判错。
3. `tools/check_content.py --strict` 进 CI，保证这类题不会悄悄变多。

## 六、验证

- `python tools/check_content.py` → 12,393 道真题，严重问题 11 道（0.09%）
- `python -m pytest tests/test_check_content.py -q` → **5 passed**
- 5 条用例分别锁住：干净题库通过、无正确选项算严重且 `--strict` 退出码 1、
  无选项不算严重、类比推理短题干不算题干为空、空题干算严重

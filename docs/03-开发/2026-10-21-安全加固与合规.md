# 2026-10-21 安全加固与合规补齐

> 背景：2026-10-21 的项目评估把「局域网无鉴权」「富文本实体编码绕过」
> 「SSRF 校验与连接分离」「无代码许可」列为公开分发前的阻断项。
> 本文记录这轮修复的模型、实现与残留风险。

## 1. 访问模型：默认只开本机，`--lan` 才要令牌

### 修复前

`run.py` 与桌面壳都监听 `0.0.0.0`，同一 Wi-Fi 下任何设备都能直接调用
`/api/data/reset`、`/api/backup/import`、`/api/settings` 等写接口。
`/api/data/reset` 的 `confirm=true` 只是防误触，不是访问控制。

### 修复后

| 启动方式 | 监听地址 | 是否需要令牌 |
|---|---|---|
| `python run.py` / `start.bat` / 桌面 exe 双击 | `127.0.0.1` | 否（只服务本机） |
| `python run.py --lan` | `0.0.0.0` | 是 |
| `desktop.py --lan` | `0.0.0.0` | 是 |

- 令牌来源：环境变量 `GOSHORE_ACCESS_TOKEN`；没有则每次 `--lan` 启动随机生成
  （`secrets.token_urlsafe(18)`），并在控制台/桌面日志打印带令牌的手机地址。
- 首次访问 `http://<IP>:8765/m/?token=...` 校验通过后写入 HttpOnly Cookie
  （`goshore_access`，SameSite=Lax，30 天），随后 303 跳到去掉 `token` 的地址，
  避免令牌留在浏览历史 / Referer。
- 也支持 `X-GOSHORE-Token` 请求头；API 无令牌返回 401，页面重定向到 `/login`。
- 非回环请求在**没有配置令牌**时失败关闭（403），不会静默放行。
- `/login` 与 `/api/health` 是唯一免令牌路径；登录后的 `next` 只允许站内绝对路径，
  挡 `//evil.com` 与绝对 URL 开放跳转。
- `TestClient` 默认来源 `testclient` 与回环地址直接放行，仅用于测试。

实现位置：`app/access.py`（纯函数，可复用）、`app/main.py` 的 `_access_guard`
中间件与 `/login` 路由、`run.py`、`desktop.py`。

### 兼容性变化

- 双击 `start.bat` / 桌面 exe 不再自动开放手机访问；需要手机时显式加 `--lan`。
- README、启动提示、桌面日志均改为「默认只监听本机」；旧版「无鉴权」说明已删除。
- 局域网仍是 **HTTP 明文**，令牌与题目内容都可被同网段嗅探；令牌只解决「谁能调接口」，
  不解决窃听。不可信网络仍应只用本机模式。

## 2. 富文本净化：实体编码绕过

### 根因

旧实现只对 `href/src` 原文做 `javascript:` 前缀判断，但浏览器会先解 HTML 实体：

```html
<a href="jav&#x61;script:alert(1)">x</a>
```

`jav&#x61;script:` 不以 `javascript:` 开头，却会被浏览器还原成 `javascript:`。
同理 `&Tab;`、`&#10;` 等控制字符可以拆开协议名。

### 修复

`static/shared/sanitize.js` 的 `sanitizeTag` 在协议判断前：

1. 解码数字实体（十进制/十六进制）与少量会拆开协议名的命名实体
   （`colon`、`tab`、`newline`、`sol`、`bsol` 等）；
2. 去掉解码后的空白/控制字符再匹配；
3. 属性值统一**重新转义**后输出（`escText`），所以解码不会让值逃出引号。

未知命名实体保留原文，宁可少认；`data:` 仍只允许 `data:image/(png|jpeg|gif|webp|bmp);base64,`。

验证：`node tools/check_xss_sanitize.mjs`（危险构造、正常保留、双端同源、篡改自检），
`python -m pytest tests/test_security_hardening.py`。

## 3. SSRF：校验与连接使用同一个 IP

### 根因

旧 `fetch_url_text` 先 `assert_safe_url(url)` 做 DNS 解析并检查 IP，然后
`httpx` 按**域名**再解析一次建立连接。两次解析之间攻击者可以把域名改指
`127.0.0.1` / `169.254.169.254`（DNS rebinding），校验形同虚设。

### 修复

`app/importer.py` 新增 `_pin_safe_url(url) -> (连接 URL, Host 头, TLS SNI)`：

- 只解析一次，要求**所有**返回 IP 都不在禁止段；
- 连接 URL 的主机名直接换成刚校验的 IP；
- `Host` 头保留原域名；
- HTTPS 通过 httpcore 的 `sni_hostname` 扩展按原域名做证书校验与 SNI；
- `httpx.AsyncClient(trust_env=False)`，避免环境代理按域名重新解析；
- 重定向仍手动逐跳跟随，**每一跳重新解析并固定 IP**；目标同样过黑白名单。

验证：`tests/test_security_hardening.py` 新增「连接打到固定 IP、Host/SNI 仍是原域名」
用例；原有内网/保留地址矩阵、重定向回内网、超大响应截断用例继续通过。

## 4. 其他修复

- **DNS rebinding 防护**：回环来源的请求还必须带**回环 Host**（`localhost`/IP
  字面量/TestClient 的 `testserver`）。否则攻击者把域名解析到 `127.0.0.1` 时，
  socket 来源是回环、Host 却是攻击者域名，会绕过“本机免令牌”规则。非回环
  请求本来就要令牌，不受这条影响。
- **安全响应头**：所有响应统一补 `X-Frame-Options: DENY`（防点击劫持）、
  `Referrer-Policy: no-referrer`（`?token=` 不经 Referer 外泄）、
  `X-Content-Type-Options: nosniff`（防静态文件被嗅探成脚本）。
- **本机进程控制**：`/api/open_app` 会执行 `adb` 并启动模拟器，现只允许回环来源；
  局域网请求即使持有令牌也返回 403，避免手机端遥控电脑进程。
- **CORS**：删除 `allow_origins=["null"]`。任意本地 HTML 文件不再能借
  `Origin: null` 调用本机写接口；仅保留 `http://127.0.0.1:8765` 与
  `http://localhost:8765`（同源页面本来也不需要 CORS）。
- **许可**：新增 `LICENSE`（MIT，仅代码）与 `NOTICE.md`（题库内容不适用 MIT，
  示例库版权归原权利人，接受权利人删除请求）。README 增加「许可与内容版权」。
- **依赖**：`requirements.txt` / `requirements-desktop.txt` 固定到本轮验证版本，
  CI 固定 `pytest==9.1.1`；Release workflow 打包前先跑全量测试。
- **CI**：`Build & Test` 增加 16 个 `tools/check_*.mjs` 前端静态校验，避免只跑 Python
  时前端共享层漂移无人发现。
- **APK 口径**：Release 不附带 APK；2026-10-21 晚用本机 Chaquopy 工具链重建并归档
  `dist/goshor-20261030.apk`（299,950,156 B，versionCode 3 / 1.2，含行测/申论/国考 AI 框架、
  手机直接拍照答疑、模型名 400 修复、共享层与安全加固），旧 APK 已删除；仍为单库 `goshor.db` 形态。

## 6. 残留风险（未在本轮关闭）

1. **HTTP 明文**：局域网令牌与题库内容可被同网段嗅探；彻底解决需 HTTPS
   （自签证书会带来手机信任提示），本轮未做。
2. **令牌在控制台/日志**：`--lan` 会把令牌打印到终端与桌面日志，方便首次登录，
   但日志被他人读到即等于拿到令牌；怀疑泄露应换 `GOSHORE_ACCESS_TOKEN` 重启。
3. **无速率限制**：令牌空间足够大（约 24 字符 URL-safe），但登录接口没有失败退避；
   公网暴露不在支持范围。
4. **同步加密未独立审计**：WebDAV 的端到端加密是自定义方案，仍需密码学评审。
5. **APK 未重建**：见上，安卓原生壳与最新后端/前端存在版本差。
6. **CSP**：页面大量内联脚本/样式，未加严格 Content-Security-Policy；XSS 主要靠
   服务端输出转义 + 前端白名单净化，不是纵深防御。

# 内容抽检与规则校验

> 目标（P4）：把「题库里有没有坏题」从一次性人工排查，变成每次导入后都能跑、
> 结果可复现、坏题能定位到具体文件的一套流程。

## 为什么需要

题库的 23,491 篇内容来自 Obsidian 笔记的批量解析。解析器不会抛异常，只会
**静默产出坏数据**：选项被截成两项、`correct` 全为 false、解析讲的是上一道题、
资料分析的材料指纹对不上。这类题不会让程序崩溃，但会让用户答错一道本来会做的
题——一次就足够让人卸载。

P0 的 `tools/check_content.py` 已经能查「选项数 / 正确选项 / 题干为空 / qid 重复」
这几类硬伤。P4 在此基础上做两件事：

1. **规则校验**：补上标签、重复选项、HTML 残留、qid 格式、模块白名单、材料
   指纹、答案分布等规则，并按「严重 / 提示」分级；
2. **确定性抽检**：按模块分层、种子可复现地抽 N 道题，生成带勾选框的
   Markdown / HTML 抽检单——规则只能覆盖已知坏法，答案对不对、解析讲得是不是
   本题，最终还得人眼看。

## 两条命令

```bash
# 规则校验（默认自动找 data/content.db，找不到再用 data/goshor.db）
python tools/check_content.py --db assets/content-sample.db
python tools/check_content.py --strict        # 有严重问题时退出码 1，可接 CI

# 抽检单：30 道，固定种子；Markdown 打屏或落盘，可选 HTML / JSON
python tools/sample_content.py --db assets/content-sample.db --n 30 --seed 20261021 \
    --out reports/sample.md --html reports/sample.html --json reports/sample.json

# 只抽规则命中过的题，优先人工复核
python tools/sample_content.py --only-flagged --n 20
```

`--db` 省略时依次探测 `data/content.db`、`data/goshor.db`；两个都没有会直接
报错退出，不会新建空库。

## 规则与分级

严重（`--strict` 退出码 1）：

| 规则 | 判定 | 为什么严重 |
| --- | --- | --- |
| 选项数异常 | 有选项但不是 4 项 | 选项缺失，题已不可答 |
| 选项标签异常 | 4 选项时标签不是恰好 A/B/C/D，或标签重复 | 判分/回显会错位 |
| 无正确选项 | 4 项里 `correct` 一个都没有 | 用户永远答不对 |
| 多正确选项 | `correct` 多于一个 | 单选题出现多答案 |
| 题干为空 | 去空白后长度 < 2 | 解析失败 |
| qid 重复 | 同一 qid 出现多次 | 错题本/统计按 qid 聚合会串题 |
| 材料指纹不一致 | 资料分析重算指纹 ≠ 库内 `material_fp` | 同材料小题会挂错组 |

提示（只报告，不阻断）：

| 规则 | 判定 | 说明 |
| --- | --- | --- |
| 无选项（判断题/主观题） | `options` 为空 | 正常题型，不是坏题 |
| 题干过短 | 非判断推理且 < 8 字 | 类比推理天然短，故排除该模块 |
| 解析过短 | `official` < 20 字 | 多半被截断 |
| 难度缺失或非法 | 不是 easy/mid/hard | 筛选与组卷会漏题 |
| 资料分析缺材料 / 缺指纹 | 无 `material` / 无 `material_fp` | 影响 AI 资料档案 |
| 选项文本全空 | 4 项 text 都为空 | 图片选项未落文本 |
| 选项重复 | 规范化空白后文本重复 | 常见于解析串行 |
| 选项仅标签（疑似图片题） | 每项 text 恰等于 label | 需确认选项图随题展示 |
| HTML 残留 | 去掉允许标签后仍有 `<...>` | 渲染可能破版 |
| qid 格式异常 | 空或不匹配 `^[A-Za-z0-9][A-Za-z0-9_.#-]{0,39}$` | 导入/同步的稳定键 |
| 模块不在白名单 | 不属于六个模块 | 分组、统计会落空 |
| 答案分布偏斜 | 单模块 ≥20 题且某标签占比 ≥55% | 可能是解析把答案错位到同一项 |

HTML 允许的标签是题干/解析正常会用到的富文本：`p br img sub sup b strong em i
u span table thead tbody tr td th`。图片题的 `<img>` 不算「HTML 残留」。

## 抽检单怎么生成

- **分层**：默认六个模块按题量占比分配名额；某模块不够时，余数按小数部分
  分给其它模块。`--module 资料分析 --module 判断推理` 可只抽指定模块。
- **可复现**：候选先按 `id` 排序，再用 `random.Random(f"{seed}:{模块}")` 抽样；
  同一个 `--seed` + 同一个库，抽出的题与顺序完全一致。
- **口径一致**：每道题的标记直接调用 `check_content.analyze_doc()`，所以抽检单
  上的「严重 / 提示」与体检报告不会出现两套说法。
- **产物**：Markdown 适合贴进 issue / 归档；HTML 自带打印样式，适合打出来逐题
  勾选；JSON 给自动化用，含 `id/qid/path/module/flags`。

抽检单每题五段：题干、选项（正确项打 ✓）、答案与难度、解析、四个勾选项
（题干可读 / 选项完整 / 答案与解析一致 / 解析讲的是本题）。题干里的图片会
保留成 `[图片：路径]`，方便核对图片是否真的抓下来了。

## 推荐流程

1. 每次批量导入后先跑 `check_content.py --strict`，严重问题必须清零再继续；
2. 看提示项的计数，若某一类突然涨（例如「选项仅标签」从 14 涨到 200），
   说明解析器改了行为，先修解析器而不是逐题修库；
3. 每周抽 30 道（固定种子轮换，例如按周改 `--seed`），人工勾完抽检单；
4. 抽检发现的「答案错 / 解析错」无法被规则覆盖，回写到题源笔记后重新导入，
   并在 `docs/04-评审/` 留一次记录。

## 实现说明

- `analyze_doc(r, dup_qids, qid_count)` 是唯一规则入口，`check_content.py` 的
  主循环和 `sample_content.py` 都调用它；新增规则只改这一处。
- 材料指纹算法在 `app/db.py:_material_fingerprint()`。工具要能脱离 app 包
  单独运行，所以 `check_content.py` 复制了一份；`tests/test_sample_content.py`
  会用 `app.db` 的权威实现对多组材料交叉比对，防止两边漂移。
- `data/content.db` 在开发沙箱里可能因权限不可读（约 449 MB）。本地验证规则
  与抽检单时用 `assets/content-sample.db`（240 真题，随仓库分发）；它同样覆盖
  六个模块、图片题、资料分析材料，足以回归工具本身。
- 抽检单写到 `reports/`（已在 `.gitignore`），不随仓库提交，避免把用户题库内容
  带进版本历史。

## 局限

- 规则只能查「结构」，查不了「答案是否正确」「解析是否在讲本题」；这两件事
  必须靠抽检。
- 「选项仅标签」对图形推理是正常形态（选项图在题干里），所以只给提示，不阻断。
- 「答案分布偏斜」是统计信号，不等于坏题：某些模块答案确实集中在 B。它只用来
  决定「先抽哪个模块」。
- 材料指纹只对 `module='资料分析'` 校验；其他模块的材料字段不做完整性判断。
- 抽样的随机性只保证「同种子同结果」，不保证跨 Python 版本完全一致（`random`
  的 Mersenne Twister 算法稳定，但不要依赖跨大版本复现）。

## 测试覆盖

`tests/test_check_content.py`（5 条）锁住旧口径：干净库 0 严重、缺正确选项是
严重、判断题无选项不严重、类比短题干不误报、空题干严重。

`tests/test_check_content_rules.py`（6 条）锁住新规则：标签重复/选项重复分级、
HTML 残留只抓真残留（允许标签放过）、qid 格式与模块白名单是提示、材料指纹
不一致是严重、答案分布偏斜按模块统计、JSON 报告的 severity/issues 结构。

`tests/test_sample_content.py`（7 条）锁住新工具：同种子可复现、模块过滤与
n 超量、`--only-flagged` 只抽坏题、三种产物落盘、答案/解析渲染、HTML 转义、
指纹算法与 `app/db.py` 一致。

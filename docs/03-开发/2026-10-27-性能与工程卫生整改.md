# 性能与工程卫生整改（2026-10-27）

> 状态：已实现并在本地跑通；改动尚未发布 Release，随下一次发版生效。
> 范围：`app/` 后端热路径、`static/shared/` 前端兜底、`tests/`、仓库工程配置。不含 Android 侧与题库内容。

## 为什么做

第二轮评估对 428 MB 真实题库（23,491 题）+ 20,021 条作答做实测，发现的问题不是"代码丑"，而是**能直接量到用户感知的慢和查不到**：

- 首页 `/api/stats` 单次 **419 ms**，是全站最慢请求；
- `documents` 是带 `LEFT JOIN` 的 TEMP VIEW，任何聚合查询都退化成"先把 23,491 行整表物化"，同一语义走视图比走底层表慢 **20–30 倍**；
- 全站零压缩，`/app.js` 367 KB、`/vendor/three.min.js` 608 KB 全裸传；
- 后端 `import logging` 计数为 **0**，`print()` 29 处，线上问题只能靠 print 猜；
- 无 lint / 无覆盖率配置，`requirements.txt` 漏声明 `openpyxl`（`.xlsx` 导入必炸）。

本轮按 P0→P3 的顺序把这些逐条修掉，**每一条都先测出基线、改完再测一遍**，不靠感觉判断收益。

## 改了什么

### P0-1 视图聚合退化（最大单点收益）

`app/db.py:743 _create_shared_views` 的 `documents` TEMP VIEW 原先写成：

```sql
SELECT d.id, ..., COALESCE(o.difficulty, d.difficulty) AS difficulty, ...
FROM shared.documents d LEFT JOIN doc_overrides o ON o.doc_id = d.id
```

只要视图里挂 JOIN，SQLite 就无法把它展平进外层查询，任何"小表 JOIN documents"都会退化为整表物化。改成**相关标量子查询**后语义等价、且可被完全展平：

```sql
COALESCE((SELECT o.difficulty FROM doc_overrides o WHERE o.doc_id = d.id), d.difficulty) AS difficulty
```

> 先试过"`doc_overrides` 为空则省掉 JOIN"的条件分支，**无效**——库里确实有 2 行 override，快路径永不触发，`/api/notes` 仍 123.9 ms。

配套：

- `app/db.py:1172` 新增 v13 迁移，建 `idx_answers_doc ON answers(doc_id, id, correct)`；
- `app/db.py:2893 stats_overview` 的连续天数/每日达标从"把 `created_at` 全表拉到 Python 再 `strftime`"改为 SQL 日桶聚合，两条重复扫描合并为一条；
- `app/db.py:3358 time_analysis` 改两段式取数：先用覆盖索引 `SELECT id, module` 建字典，再流式扫 `answers` 热循环，`title`/`kaodian` 只为最终展示的少量行按主键回查。热循环用**元组而非 dict**（同循环 dict 8.0 ms / 元组 3.9 ms）；
- `app/db.py:2177 list_wrong_book` 去掉 `SELECT d.*`（含 72 MB `data` 列），正确答案改用 `json_each` 就地取；新增可选 `limit` 参数（`limit<=0` 保持全量，向后兼容）。

### P0-2 全站零压缩

`app/main.py:352` 加 `GZipMiddleware(minimum_size=1024)`（在 CORS 之后）。SSE 流式响应由 Starlette 自动排除，不会被缓冲。实测 `/api/wrong-book` 3.53 MB → 332 KB（9.4%）。

### P1-1 `connect()` 每请求重放 DDL

`app/db.py:889 connect()` 每次连接都要 `executescript(PERSONAL_SCHEMA)`（23 条 `CREATE TABLE IF NOT EXISTS`）+ `PRAGMA table_info(answers)` + `BEGIN IMMEDIATE` 写锁探测。加进程内就绪登记 `_PERSONAL_READY`（配 `_URI_CACHE` 缓存 `as_uri()`），命中即只跑 `_create_shared_views` 后返回。

> **踩坑**：初版连版本检查也跳过，`tests/test_personal_db_init.py::test_connect_migrates_outdated_personal_db` 立刻失败（`assert 3 == 13`）。该测试模拟"还原旧备份"——快速路径看不到就再也不会补表补列。修法：**保留 `_personal_needs_init()`（仅 0.005 ms），只省 executescript + table_info 两条 DDL**。版本变旧时主动落回慢路径重建，并新增 `db._forget_personal_ready()`，由备份恢复路径 `app/main.py:_replace_db_file` 显式清登记。

### P1-2 async 路由里跑同步 CPU 活

140 条路由里 137 条已是 `def`（跑线程池），真正的问题是少数 `async def` 内部直接做同步解析：

- `app/importer.py:296` CSV 分支去掉 `pandas.read_csv`，改标准库 `csv`（pandas 冷启动 **923 ms** 全耗在 `import pandas`，热态也比标准库慢 30 倍）；
- `app/main.py:1497 api_import_file_preview`、`app/main.py:2227 api_backup_import` 的解析/解压/文件覆盖全部改走 `run_in_threadpool`。

### P2-1 logging 体系（原先为 0）

新建 `app/logging_setup.py`：`goshore` 命名空间、`GOSHORE_LOG_LEVEL` 环境变量、stderr + `RotatingFileHandler(<DATA_DIR>/logs/app.log, 1 MB × 3)`，装不上只 warning 不抛。29 处 `print` 全部改为带级别的日志，`app/main.py:lifespan` 首行初始化。

### P2-2 收窄宽捕获

全仓 `except Exception` 紧跟 `pass` 的 16 处逐条收窄为具体异常类型并补日志（`app/config.py` 的 `load_settings()` 是典型：`settings.json` 解析失败原本静默 `pass`，用户看到的是"设置莫名重置"）。

### P3 工程卫生

- 新增 `pyproject.toml`：ruff（`select = ["F","E9","I","UP","RUF100"]`）、pytest、coverage 配置；`ruff check .` 从 **191 errors** 修到 **All checks passed**；
- `pytest-cov` 接入，当前覆盖率 **60%**；
- `requirements.txt` 从 5 行补成按用途分组的完整声明，**补上 `openpyxl`**——这是本轮发现的真 bug：`pandas.read_excel` 读 `.xlsx` 依赖它，缺了必炸，而 CSV/JSON 路径都正常，所以长期没被发现；
- 新增 `tests/test_importer_formats.py`（14 条，钉住 CSV/XLSX/DOCX/PDF 各分支）、`tests/test_frontend_error_guard.py`（9 条）；
- `static/shared/core.js:850` 新增 `ErrorGuard`：`window.onerror` + `unhandledrejection` 兜底，同一 `message+source+line` 10 秒内去重、每次会话最多提示 3 条，完整堆栈进 `console.error`。**刻意不弹模态、不清空视图**——局部报错不该让整页变成错误页。双端共用，不需要各端改代码；
- 连接泄漏：`sqlite3.Connection` 子类工厂 `_AutocloseConnection` 兜底 126 处"开了不关"的路径；`app/sync_webdav.py` 的响应对象改为 `@contextlib.contextmanager` 的 `_call`；
- 清理 139 个 `.pytest_tmp*` 目录与全部一次性探针脚本。

## 两项评估后决定不做

| 项 | 为什么不做 |
| --- | --- |
| 抽 `static/shared/` 消除双端漂移 | 实测 `app.js` 82 个函数 / `m.js` 106 个，同名 47 个中**完全相同仅 6 个**（合计约 1.85 KB），41 个差异多为**有意分叉**（移动端 padding 30→26 px、`3 分 05 秒`→`3:05`、`toast` 默认 3200 ms vs 1800 ms、`draftResume` 走 hash 路由 vs 直调 `runPaper`）。整体重构风险远大于收益。**唯一真漂移**是移动端 `api()` 缺 `AbortController` / `AbortError` 判断，建议后续单独补约 20 行，不随本轮做 |
| 引入 eslint | 仓库前端是无构建原生 JS（`index.html` 直接 `<script src>`），引入需约 200 MB Node 工具链，7158+6660+833 行首跑会出数百条告警。替代方案 `node --check` 零依赖，本轮已用 |

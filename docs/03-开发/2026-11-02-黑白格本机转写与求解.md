## §A 目标与边界

| 编号 | 目标 | 判定方式 |
|---|---|---|
| G1 | 本机把「3×3 九宫格 + 每格 3×3 黑白小格 + 4 个选项」逐格转写成 ■/□ | 真实截图 13 组矩阵与人工核对一致 |
| G2 | 本机枚举黑白叠加规律并给出唯一答案 | 该截图输出「按列去同存异 → D」 |
| G3 | 转写/答案作为底稿注入答疑，模型不得改写 | 注入测试断言块在最后一条 user 消息里，system 有硬约束 |
| G4 | 识别不准或解不出时明确「无法判定」，不得猜 | 非该布局返回空；无规律时块内写明禁止给选项 |

**不做**：
- 不做其他图形推理类型（平移/旋转、数量类、立体类）的自动求解；
- 不做手机端 UI 的本机转写展示（仅桌面端展示，手机端沿用现有气泡）；
- 不在识别失败时给任何兜底答案。

## §B 现状核对（实测）

| 项 | 实测结果 | 影响 |
|---|---|---|
| 用户截图 | 715×613 PNG；主线 x=77/195/314/432，y=44/156/273/392；选项框 y≈426–544 | 框线可由投影法稳定检测 |
| 转写结果 | 9 格矩阵 + 4 选项已人工采样确认（1-1 `100/010/100` … D `101/110/000`） | 可作为验收基准 |
| 规律 | 按行叠加均不成立；按列 XOR（去同存异）第 1、2 列全通过，第三列推出 D | 求解器必须按列优先验证 |
| 内置 AI 事故 | 会话 1 第 21/25 条编造逐格验证，第 23 条自认无法可靠分辨 | 需要用本机转写兜底 |
| Pillow | 本机 12.3.0，numpy 2.3.5；已作为可选依赖写入 `requirements.txt` | 缺失时 `ask_grid_block` 返回空串，自动降级 |

## §C 方案与取舍

- **选定**：`app/gridread.py` 做「框线检测 → 逐格采样 → 矩阵」；同模块枚举「方向 × 运算 × 对称」求解；`ai.ask_grid_block()` 把结果拼进最后一条 user 消息；ASK_SYSTEM 增加第 12 条硬约束。
- **否决**：让模型先转写再由服务端校验。模型转写本身不可信，校验也无从对齐。
- **否决**：直接用 OpenCV/模板匹配所有图形。范围过大，且会引入新依赖与误判。

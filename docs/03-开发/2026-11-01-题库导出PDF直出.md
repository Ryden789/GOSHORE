## §A 目标与边界

| 编号 | 目标 | 判定方式 |
|---|---|---|
| G1 | 导出面板默认格式为 PDF，点一下直接下载文件 | 浏览器点击后收到 `%PDF-` 文件头 |
| G2 | PDF 内容与「可打印网页」逐字一致（试题在前、答案解析在后、材料只印一次） | 同一参数下 PDF 页数与网页打印版一致；页面内答案数、图片数与 HTML 一致 |
| G3 | 本机缺 Playwright / Chromium 时不阻塞用户 | 接口返回 501，前端自动退回可打印网页并提示 |
| G4 | 题干图片在 PDF 中正常显示 | PDF 内图片对象数 > 0；人工抽页核对 |

**不做**：
- 不为手机端（安卓 `goshor_server.py`）实现 PDF：无 Chromium，继续走 HTML 导出/分享。
- 不改打印页的排版与内容拼装（复用同一份 `api_export_print` 结果）。
- 不引入在线渲染服务或云端转换。

## §B 现状核对（实测）

| 项 | 实测结果 | 影响 |
|---|---|---|
| 旧导出链路 | `GET /api/export/print` 只返回 HTML，用户要自己 Ctrl+P 另存 | 多一步操作，手机浏览器另存体验差 |
| 拼装逻辑 | `app/print_export.render_html()` 已按传入顺序编号 1..N | 可直接复用，避免两套导出漂移 |
| 题干图片 | 打印页使用 `<img src="/img?path=...">`，相对站内路径 | Chromium `set_content` 无文档地址，需注入 `<base>` |
| 依赖 | 桌面 `requirements.txt` 原先没有 Playwright | 需声明可选依赖并在设置页说明安装命令 |

## §C 方案与取舍

- **选定**：新增 `GET /api/export/pdf`，直接调用 `api_export_print()` 取 HTML，再交给 `app/pdf_export.html_to_pdf()` 渲染；A4、四周 12 mm、`print_background=True`。
- **选定**：`html_to_pdf()` 在 `<head>` 注入 `<base href="{request.base_url}">`，让 `/img?path=` 落到本机服务。
- **选定**：Playwright 缺失抛 `PdfUnavailable`，路由转 `HTTPException(501)`；前端捕获后自动打开可打印网页并提示。
- **选定**：文件名按「整卷名 / 自定义标题 / 模块」生成，去掉 Windows 非法字符，`filename*` 走 UTF-8。
- **否决：后端用 WeasyPrint / wkhtmltopdf**——字体与分页同浏览器差异大，题干图片与表格容易走样，且需额外系统依赖。
- **否决：前端 jsPDF 拼页**——无法复刻网页打印排版，图片与分页都要重写。
- **否决：把 Chromium 打进 exe**——体积增加约 150 MB，超出桌面包预算；改为可选依赖 + 501 降级。

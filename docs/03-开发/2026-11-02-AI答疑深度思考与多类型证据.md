## §A 目标与边界

| 编号 | 目标 | 判定方式 |
|---|---|---|
| G1 | 新增「深度思考」设置开关，默认开；开启时答疑不再强制 `thinking=disabled`，看图等待上限放宽 | 设置项落盘；`stream_chat` 依开关决定 payload；关闭时行为与旧版一致 |
| G2 | 图形推理其他类别（非黑白格）输出本机像素统计证据：图块数、墨迹占比、连通块数、封闭区域数、左右/上下对称度 | 合成图测试命中；无法解码返回空串 |
| G3 | 资料分析仅在题干标签与数字可解析时给可复算算式（现期/基期/部分/整体），不确定返回空串 | 能算的用例给出算式与结果；缺标签不输出 |
| G4 | 言语/逻辑判断输出本机关联词与位置标记（转折、因果、结论、对策、条件），不替模型下语义结论 | 含标记的文段命中；无标记返回空串 |
| G5 | 答疑提示词补「四条独特性总则」；本机证据统一以 `evidence` 事件推到前端折叠展示 | 提示词含总则；桌面/手机均能渲染多块证据 |
| G6 | 桌面答疑输入框旁提供「深度思考」按钮，按次覆盖设置项（不写回设置，不改变默认值） | 按钮状态可切换；请求体 `think` 原样透传到 `stream_chat` |
| G7 | 图推给出固定排查顺序（结构 → 组成 → 位置/样式/属性/数量 → 立体）与「命中即停」规则，替代「先穷举四大类」 | `ASK_SYSTEM` 第 8 条与 `ask_graph_block` 均含顺序与停止条件 |
| G8 | 每类题型都有可执行的思考框架（资料分析/数量/言语 8 类/判断 7 类/常识/申论 5 类/综应 C 类 4 类），方法从 `知识点综合/` 整理讲义提炼并标注出处；命中题型时注入并按步作答 | `app/thinkframe.py` 27 条框架；答疑提示词首部注入 + evidence 折叠展示 |
| G9 | 自评并修掉框架的已知缺陷：题干普通词不把题型带偏；出处路径可校验；补综应 C 类与「有图无文字」兜底 | 误判用例返回正确题型或 `None`；出处首路径真实存在；`image_frame()` 兜底生效 |

**不做**：
- 不做平移/旋转/立体类图推的自动求解（只给像素统计，规律仍由模型依据证据自检）；
- 不做整卷资料分析的自动读数（截图中数字无法可靠 OCR，缺标签一律不输出）；
- 不改变做题页的讲题链路（`/api/explain`），只改自由答疑；
- 不引入新依赖（复用既有 Pillow + numpy，缺失时静默降级）。

## §B 现状核对

| 项 | 现状 | 影响 |
|---|---|---|
| `ai.stream_chat` | `use_vision=True` 时写死 `payload["thinking"]={"type":"disabled"}`，`deadline=60s` | 看图答疑没有深度思考，长推理容易被掐 |
| `config.DEFAULTS` | 无 `ai_thinking` 键；设置接口用 pydantic 字段白名单 | 需同时改默认值、`SettingsIn`、手机端默认值与保存分支 |
| 证据注入 | 只有黑白格走「本机算」；其他题型仍靠模型自由发挥 | 需要把像素统计/复算/结构标记做成同样的可核对证据 |
| 前端渲染 | 只处理 `type=grid` 一个折叠块 | 需泛化为多块 `evidence` |
| 测试基线 | pytest 1447 passed（2026-11-02） | 新增测试后应全绿 |

## §C 方案与取舍

- **选定**：开关式深度思考。默认开（用户明确要求「恢复」），关闭时保留 `thinking=disabled` 与 60 秒上限，给慢网络/求快场景留出口。
- **选定**：证据按题型分模块（`figfeat` / `datacalc` / `textmark`），每个模块可独立失败、失败即返回空串，不阻塞答疑。
- **选定**：证据分两级——注入提示词的「底稿」+ 推送前端的「可核对块」。前者让模型必须引用，后者让用户能自己核对。
- **否决**：无条件全开深度思考。看图 + 思考会把 60 秒等待变成数分钟，对手机端不可接受，因此保留开关。
- **否决**：为每类图推写确定性求解器。除黑白格外的规律依赖语义判断，强行求解会重蹈「编造验证」的覆辙。
- **否决**：用 OCR 读资料分析截图数字。识别不可靠，算错比不算更糟。

# 质量门进 CI（2026-10-26）

> 状态：已实现并在本地跑通；对应提交见 `git log`。
> 范围：GitHub Actions 常规 `build.yml`，不含手动发布流程 `release.yml`。

## 为什么做

此前 CI 只跑 pytest 与 15 个 Node 校验器；E2E、AI golden 评测和示例库内容规则只在本地手动执行。结果是：本地能过、远端没人跑，测试库隔离缺陷曾长期不被发现。P0-2 把这三类检查变成每次 push / PR 的必过项。

## 改了什么

`.github/workflows/build.yml` 新增 `quality` job（`needs: test`）：

- 环境：ubuntu-latest，Python 3.13，20 分钟上限，`PYTHONUTF8=1`；
- 安装 `playwright==1.60.0` 与 Chromium；
- `python scripts/e2e_mobile.py`：HTTP 冒烟 + 33 路由 + 79 项断言；
- `python scripts/eval_ai.py --min-score 95`：33 条 golden，低于 95 分失败；
- `python tools/check_content.py --db assets/content-sample.db --strict`：240 道示例库，出现严重问题即失败。

`scripts/e2e_mobile.py` 同时做了三处 CI 适配：

1. 没有本机 `.tools/mobile_prep/goshor.db` 时回退到仓库内 `assets/content-sample.db`，不再依赖构建产物；
2. 新首页的等待选择器从 `.stat-grid` 改为 `.study-home`（完整统计已折叠进 details，旧选择器不可见）；
3. 桌面无障碍用例回 `#/overview`；移动搜题 Enter 改用 `locator.press("Enter")`，避免 `focus()` 后被重渲染抢焦点。

校验器总数随远端 UI 提交的 `tools/check_layout.mjs` 增至 **16 个**。

## 验证

| 检查 | 结果 |
| --- | --- |
| E2E | 79/79 PASS（33 路由） |
| AI golden | 33/33，100.00 分 |
| 示例库内容 | 240 道，严重 0，提示 15 |
| pytest | 1005 passed（P0-1 基线，本轮未改业务代码） |
| Node checker | 16/16 EXIT=0 |

E2E 第一次接入时出现过 1 项移动端 A11Y 失败：`focus()` 后列表被重渲染，`keyboard.press("Enter")` 落到了 body。改为 locator 直接 press 后稳定通过；这不是产品功能回退。

## 边界

- APK 构建仍未进 CI：Android 依赖本机 Chaquopy / Gradle / SDK / wheels，且当前 APK 约 300 MB、debug 签名；留在 P0-3。
- 手机相机的真机唤起仍未验收；留在 P0-4。
- `quality` job 依赖 Playwright 下载 Chromium，CI 时间会比纯 pytest 长；失败时先看 E2E 的路由/断言名。

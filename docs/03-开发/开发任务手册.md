## A. 已知 Bug 修复（优先级最高）

### A1. 移动端"论证评价"材料加载失败
**文件**：`android/app/src/main/python/goshor_server.py`  
**行号**：约 L720（`do_GET` 函数内）  
**现象**：手机端打开「论证评价」页时，材料列表和题目详情返回 404 或空数据。

**根因**：桌面端把 `/api/argument/overview` 和 `/api/argument/material/{mid}` 注册在 `do_GET`，移动端这两个接口之前只在 `do_POST` 里。2026-10-05 已经补上了 GET 路由，但 **Chaquopy 打包的 JSON 数据源没进 APK**。

**验证方法**：
1. 打开 APP → 综应专区 → 论证评价
2. 应该看到 6 篇材料的列表，点击进入详情
3. 如果看到"加载失败：not found"或"no such file"，说明还没修好

**修复步骤**（如果还没修）：
1. 检查 `app/argument_materials.json` 和 `app/argument_quiz.json` 是否存在
2. 如果不存在，从 `data/` 目录复制过来：
   ```bash
   cp data/argument_materials.json app/
   cp data/argument_quiz.json app/
   ```
3. 打开 `app/argument.py`，把第 27-28 行改成：
   ```python
   _DATA = Path(__file__).resolve().parent / "argument_materials.json"
   _BANK = Path(__file__).resolve().parent / "argument_quiz.json"
   ```
4. 重新构建 APK：`cd android && gradlew assembleDebug`

## B. 性能优化（改善体验）

### B1. 移动端路由切换时旧页面未清理定时器
**文件**：`static/m/m.js` L298-L329（`route` 函数）  
**现象**：快速切换页面时，旧页面的 `setTimeout`/`setInterval` 可能还在运行，操作已移除的 DOM 元素。

**现状**：`route` 函数里 `inRun = false` 但 **没有清理全局定时器**。

**修复步骤**：
1. 在 `route` 函数开头加一行：`clearAllTimers()`
2. 新建 `clearAllTimers()` 函数，遍历所有已知的定时器 ID 并清除
3. 把所有 `setTimeout`/`setInterval` 的 ID 存到一个全局数组里

**示例代码**：
```javascript
// 在文件顶部加：
const activeTimers = [];

// 封装 setTimeout：
function safeTimeout(fn, delay) {
  const id = setTimeout(() => {
    const idx = activeTimers.indexOf(id);
    if (idx > -1) activeTimers.splice(idx, 1);
    fn();
  }, delay);
  activeTimers.push(id);
  return id;
}

// 在 route() 函数开头加：
function clearAllTimers() {
  activeTimers.forEach(id => clearTimeout(id));
  activeTimers.length = 0;
}
```

### B3. 搜索页每次输入都发请求，无防抖
**文件**：`static/app.js` L455（搜索框）  
**现象**：用户在搜索框输入时，每敲一个字就发一次 `/api/search` 请求，浪费资源。

**现状**：搜索框的 `oninput` 事件直接触发搜索。

**修复步骤**：
1. 加一个防抖函数（300ms）
2. 只有用户停止输入 300ms 后才发请求

**示例代码**：
```javascript
let searchTimer = null;
function debounceSearch() {
  clearTimeout(searchTimer);
  searchTimer = setTimeout(() => doSearch(1), 300);
}

// 把原来的 oninput 改成：
$("#q").oninput = debounceSearch;
```

### B4. 数据库查询无索引，搜索慢
**文件**：`app/db.py`（所有查询函数）  
**现象**：题库有 23,491 道题，如果 `documents` 表没有索引，搜索会很慢。

**检查方法**：
```sql
-- 在 SQLite 里执行：
SELECT name FROM sqlite_master WHERE type='index' AND tbl_name='documents';
```

**修复步骤**：
1. 打开 `app/db.py`，找到 `_migrate()` 函数
2. 在函数末尾加：
   ```python
   # 为常用查询字段加索引
   conn.execute("CREATE INDEX IF NOT EXISTS idx_documents_module ON documents(module)")
   conn.execute("CREATE INDEX IF NOT EXISTS idx_documents_difficulty ON documents(difficulty)")
   conn.execute("CREATE INDEX IF NOT EXISTS idx_documents_year ON documents(year)")
   conn.execute("CREATE INDEX IF NOT EXISTS idx_search_text ON documents(search_text)")
   ```
3. 把 `SCHEMA_VERSION` 从 1 改成 2
4. 在 `_migrate()` 里加版本 2 的迁移逻辑：
   ```python
   if current_version < 2:
       # 加上面的索引
       pass
   ```

## D. 代码质量改进

### D1. 前端代码无模块化，全部堆在一个文件
**文件**：`static/app.js`（4129 行）、`static/m/m.js`（3753 行）  
**问题**：所有功能都在一个文件里，改一个地方可能影响其他功能。

**改进方案**：
1. 按功能拆分文件：
   - `static/js/search.js`（搜索页）
   - `static/js/practice.js`（刷题页）
   - `static/js/review.js`（复习页）
   - ...
2. 用 ES6 模块导入导出
3. 在 `index.html` 里用 `<script type="module">` 引入

**难度**：高（需要重构整个前端）  
**建议**：暂时不做，等项目稳定后再重构。

### D2. 数据库查询无参数化，有 SQL 注入风险
**文件**：`app/db.py`（所有查询函数）  
**问题**：虽然有参数化查询，但需要检查所有 SQL 语句是否都用 `?` 占位符。

**检查方法**：
搜索 `db.py` 里的 `execute` 调用，看是否有字符串拼接 SQL 的情况。

**示例**（错误写法）：
```python
# 不要这样写：
conn.execute(f"SELECT * FROM documents WHERE module = '{module}'")

# 应该这样写：
conn.execute("SELECT * FROM documents WHERE module = ?", (module,))
```

---

### D3. 异常处理过于宽泛
**文件**：`app/main.py`、`app/db.py`  
**问题**：很多地方用 `except Exception` 捕获所有异常，掩盖了真正的错误。

**改进方案**：
1. 只捕获预期的异常类型（如 `sqlite3.OperationalError`、`httpx.TimeoutException`）
2. 其他异常让程序崩溃，方便调试

## G. 安全与隐私

### G1. API Key 明文存储在 localStorage
**文件**：`static/app.js`、`static/m/m.js`  
**现象**：DeepSeek API Key 可能存在 localStorage 里，容易被 XSS 攻击窃取。

**改进方案**：
1. 不要在前端存储 API Key
2. 所有 AI 请求都通过后端转发，后端从 `data/settings.json` 读取 Key

**检查方法**：搜索前端代码里的 `localStorage.setItem.*key` 或 `api_key`。

---

### G2. 数据库文件未加密

**改进方案**：
1. 用 SQLCipher 加密数据库
2. 或者在备份时加密 ZIP 文件

**难度**：高（需要改数据库连接方式）  
**建议**：暂时不做，等用户需求明确后再做。

### Q: 修改后没有生效？
A: 检查是否需要重启服务或重新构建 APK。

### Q: 数据库迁移失败？
A: 删除 `data/goshor.db` 重新初始化（**会丢失数据**，先备份）。

### Q: APK 构建失败？
A: 检查 Gradle 版本、Android SDK 路径、网络连接。

## 附录：推荐执行顺序

1. **先修 Bug**（A 类）→ 保证现有功能可用
2. **再做性能优化**（B 类）→ 提升体验
3. **然后补齐功能**（C 类）→ 消除移动端/桌面差异
4. **最后做代码质量**（D/E 类）→ 长期维护

**每次只做一件事，做完测试通过后再做下一件。**

# GOSHORE · 页面与用户操作优化复查细则

> **文档性质**：基于当前代码复查的剩余页面体验任务书  
> **版本**：V1.0  
> **日期**：2026-10-07  
> **读者**：受托执行本项目页面优化的模型 / 工程师  
> **目标**：改善常用入口的发现效率、移动设置导航的可见性、键盘操作和弹窗焦点管理；不改变功能、业务规则、API 或数据结构。  
> **基线**：执行时以当前分支代码为准。文中路径和位置是检索起点，代码可能已变化，开始前必须重新检查。

---

## 1. 范围与原则

### 1.1 本轮范围

- 调整已有首页模块的展示顺序，让已存在的常用学习入口更早出现。
- 改善移动端设置页已有分区导航的可见性和可操作性。
- 让已有的点击式列表项可以通过键盘访问和激活。
- 完善已有每日开门题弹窗的焦点进入、弹窗内键盘操作和关闭后的焦点恢复。
- 对移动端“全部功能”页的入口密度做小范围用户观察；没有证据前不改布局。

### 1.2 本轮禁止事项

- 不添加、删除、合并或改变任何产品功能、学习规则或用户流程。
- 不改变每日开门题的拦截范围、完成条件、跳转规则或提示内容的业务含义。
- 不改变数据统计口径、题目推荐策略、组卷逻辑、API、数据库或本地存储契约。
- 不隐藏首页统计、功能入口或管理项来制造“页面更简单”的表象。
- 不把移动端功能导航改造成新的全局搜索功能；本轮只评估入口是否容易找到。
- 不引入前端框架、运行时依赖或构建步骤。
- 不覆盖工作区里与本任务无关的改动，不提交、不推送、不发布。

所有改动必须保持原有 hash 路由、按钮动作、统计数据、内容和权限规则。若实现某项建议必须改变业务行为，应停止该项并记录原因，不自行扩大范围。

### 1.3 当前已具备的体验改进（不要重复实现）

复查时当前代码已能看到以下能力，执行前仍需重新核对：

- 桌面与移动首页有首次使用提示，可说明题库为空和 AI 未配置，并链接到现有导入 / 设置页面。
- 移动端每日开门题拦截有说明，并提供“开始今日一题”直接操作。
- 桌面与移动设置页已有分区快速定位入口。
- 桌面有跳到主要内容的链接；全站已有部分焦点样式、减少动态效果和状态播报支持。
- 桌面端主要入口按类别分组，移动端“全部功能”页也按类别分组并附简短说明。

这些项目当前不作为本手册的新增任务，除非执行前发现代码已回退或功能实际失效。

## 2. 复查判断

### 2.1 确认存在、可以直接处理的项目

| 编号 | 观察 | 用户影响 | 判断 |
|---|---|---|---|
| PAGE-01 | 桌面首页的“开始学习”快捷入口在多组统计和图表面板之后；移动首页在多项统计和目标组件之后才出现常用学习入口 | 用户首屏任务完成路径偏长，尤其是已有学习记录的用户 | 可仅移动现有模块顺序，优先处理 |
| PAGE-02 | 移动设置分区导航为单行横向滚动，并隐藏滚动条 | 窄屏上后续分区按钮可能不明显 | 可改成可见的两行布局或保留明显滚动线索，不改变锚点行为 |

| A11Y-02 | 每日开门题弹窗声明了 `role="dialog"` 和 `aria-modal="true"`，但没有完整焦点管理 | 键盘焦点可能留在背景；读屏用户不一定能立即进入弹窗操作 | 完善弹窗生命周期管理，不改变拦截行为 |

### 2.2 仅需验证、目前不认定为缺陷的项目

移动端“全部功能”页集中列出多个分类和入口，代码能确认列表较长，但不能仅凭长度判断用户找不到功能。当前分类名和功能说明已提供一定帮助。本轮先做短时观察；无明显问题就不改。

## 4. 逐项细则

### PAGE-01：首页快捷入口排序

**现状定位**：

- 桌面：`static/app.js` 中 `renderHome()`；搜索“今日推荐练习”“今日学习计划”“开始学习”“quick-entries”。
- 移动：`static/m/m.js` 中 `renderHome()`；搜索“每日一题”“开始学习”“今日推荐练习”。

**问题**：

桌面首页先展示总览统计、目标、推荐练习、计划、做题量、正确率、速算趋势和学习时长，常用入口位于图表区后。移动首页在“开始学习”前显示称号、开门题状态、多项统计和目标进度。统计对回顾有价值，但用户打开首页时常见的下一步通常是继续练习、开始练习或完成复习。

**目标**：

把现有学习动作入口提前，让用户在首页更快进入已有流程；完整保留统计内容和入口，不增加新操作。

**实施步骤**：

1. 列出桌面和移动首页当前已有的入口、动作、条件显示和绑定函数，记录其原始顺序和跳转。
2. 将桌面现有“开始学习”区（随机组卷、今日复习、辨析卡、申论综应）移到统计图表之前；建议放在页面标题、续做卡和必要状态提示之后。
3. 将移动端现有“开始学习”区移到统计网格和每日目标之前；若今日开门题未完成，必须保留每日一题按钮的当前优先级和位置逻辑，不得将其与其他受限入口混淆。
4. 续做草稿卡片、空题库提示、考试日期提示和 AI 可选配置提示仍应在需要时可见；避免快捷入口遮住需要先完成的准备项。
5. 不改变“今日推荐练习”的题量、推荐方式、标题、接口或点击动作；只移动现有节点模板所在位置。
6. 检查小屏、桌面宽屏和最大字号。若快捷入口横向布局不适合小屏，可沿用现有 CSS 断点调整布局，但不得缩短到含义不明或隐藏入口。
7. 比较修改前后的 DOM / 截图，确认下方统计仍能正常滚动到达，图表与入口动作正常。

**验收标准**：

- 桌面和移动端常用入口比统计图表更早出现；首页标题及必要的状态提示仍清晰可见。
- 原有入口数量、标签、目的路由、点击动作和条件显示完全一致。
- 统计卡、目标进度、图表、错因和错题列表仍全部可访问，没有被移除或折叠隐藏。
- 未完成每日开门题时，今日一题仍清楚优先；完成后快捷入口正常出现。
- 空题库、已配置题库、未配置 AI、存在未完成草稿等状态均能正确排列，不互相遮挡。
- 至少检查桌面 1366px、平板 768px、手机 375px / 320px 和最大字号。

**验证建议**：

- 通过现有首页渲染或 E2E 路由巡检验证页面仍能正常渲染。
- 手工逐个点击快捷入口，确认仍进入原功能。
- 检查动态文本、长模块名和小视口下是否换行正常。

### A11Y-01：点击式列表项的键盘操作

**现状定位**：

- 桌面题库结果：`static/app.js` 搜索“`class="doc-item" data-id="${it.id}"`”及后续 `.onclick`。
- 移动题库结果：`static/m/m.js` 搜索“`class="sr-item" data-id="${it.id}"`”及后续 `.onclick`。
- 额外优先检查桌面首页 TOP 错题、统计卡；移动端错题列表和搜索结果。执行前重新检索所有绑定 `.onclick` 的非交互 HTML 元素。

**问题**：

部分视觉上像链接或按钮的列表项使用 `div` 并由 JavaScript 绑定点击处理。鼠标或触摸可用，但原生键盘 Tab 不会自动聚焦普通 `div`；全局焦点样式对无法聚焦的元素不起作用。仅添加 `role="button"` 也不够，因为还需要处理焦点和键盘激活。

**目标**：

让高频点击式列表项既保留当前外观和动作，也可由键盘用户访问。优先使用正确的原生语义元素。

**实施步骤**：

1. 盘点“可点击但不是 `<a>` 或 `<button>`”的元素，至少记录页面、选择器、动作和频率（高/中/低）。不要对所有 `onclick` 一律重写，很多是选项或拖动控件，需要保留对应语义。
2. 对导航到题目/页面的整行项目，优先改成 `<a href="#/...">`；对执行动作的项目使用 `<button type="button">`。若改为原生元素会破坏复杂队列或交互，则保留结构但补 `role`、`tabindex`、Enter/Space 和可见焦点样式。
3. 先处理题库搜索结果、首页高频错题项和错题本列表项；同一类组件桌面与移动分别确认，因为其行为并不完全相同。
4. 如果列表行内部还有“删除”“收藏”等子按钮，禁止让整行链接/按钮吞掉内部操作；明确事件边界和停止冒泡行为。
5. 激活元素必须有明确可访问名称。装饰图标设为 `aria-hidden="true"`；重复行标题应成为主要名称，必要时为附加统计补充说明。
6. 使用现有 `:focus-visible` 风格；检查深色和浅色主题下的焦点对比度。不得通过 `outline: none` 移除焦点而不提供等价标记。
7. 验证 Enter 激活链接；Space 激活按钮且不会导致页面意外滚动；方向键行为只在原控件模式要求时实现，不额外模拟复杂控件。

**验收标准**：

- 从页面顶部按 Tab 可到达所有处理过的高频列表项，焦点顺序符合视觉顺序。
- 每个列表项在焦点状态下有清楚的可视反馈。
- 链接用 Enter 可打开；按钮用 Enter / Space 可触发一次；无重复触发。
- 鼠标、触摸原有行为保持一致；点击嵌套的删除等操作不会误触发整行导航。
- 屏幕阅读器将其识别为链接或按钮并读出题目标题/动作含义。
- 桌面和移动端的相关静态检查、E2E 路由及操作回归通过。

**禁止事项**：

- 不把纯展示文字、图表和统计数字全部设置成可聚焦控件。
- 不只添加 `tabindex="0"` 却不支持键盘激活。
- 不改变进入题目后的题目队列、做题状态或记录写入逻辑。

### PAGE-02：移动端设置分区导航可见性

**现状定位**：

- `static/m/m.css` 中 `.m-index` / `.si-btn`。
- `static/m/m.js` 的 `renderSettings()` 中 `#sec-m-ai`、`#sec-m-look`、`#sec-m-backup`、`#sec-m-sync`、`#sec-m-upd`、`#sec-m-danger` 分区和按钮绑定。
- 桌面端 `.settings-index` 已允许换行，可作为布局参考，但不要照搬桌面尺寸。

**问题**：

移动端分区导航是单行横向滚动，并通过 CSS 隐藏滚动条。手机屏宽时只能看到部分分区按钮；没有明显的溢出提示时，用户可能不知道右侧还有更多设置区域。

**目标**：

让六个已有分区入口在手机上更容易发现，同时保留当前定位目标、顺序和滚动行为。

**优先方案**：

先尝试让按钮在窄屏换行成两行以内；如果页面高度或视觉空间不合适，再考虑保留横向滚动并增加明确但克制的可滚动提示。不得同时堆叠多种提示。

**实施步骤**：

1. 在 320、360、375、430 CSS px 下记录当前可见按钮数量和横向溢出情况，确认最窄屏上的问题。
2. 首选将 `.m-index` 改为 `flex-wrap: wrap` 或适当网格；保证六个按钮均可见且不挤压正文卡片。
3. 如果必须保留横向滚动：提供边缘渐隐、部分露出的下一项或清晰滚动提示；不要单靠隐藏滚动条的滚动容器。
4. 检查最大字号下按钮名称不截断。允许自然换行；不要只缩小字号来塞入单行。
5. 保留所有 `data-sec`、section id 和 `scrollIntoView` 行为；设置页顶栏 / 安全区域的 `scroll-margin-top` 仍须生效。
6. 键盘访问每个分区按钮时，确保浏览器会把当前聚焦按钮滚入可视区。

**验收标准**：

- 320px、375px 下六个分区均可被发现和操作；无不可见且无提示的横向溢出。
- 最大字号、深色模式下按钮文字、边框和焦点状态均清楚。
- 点击每个分区仍准确滚动到原来的 section；标题不被 sticky 顶栏遮住。
- 按 Tab 到达横向导航后，当前焦点项自动进入可视范围。
- 桌面设置导航行为与样式未被本次移动端调整破坏。

### A11Y-02：每日开门题弹窗焦点管理

**现状定位**：

- `static/m/m.js` 的 `dailyDoorPrompt()`，搜索 `function dailyDoorPrompt` 和 `role="dialog"`。
- 弹窗已有“稍后再说”和“开始今日一题”两个按钮。每天开门题触发、跳回首页和受限路由守卫不属于本任务可修改范围。

**问题**：

弹窗设置了 `role="dialog"`、`aria-modal="true"` 和标题关联，但挂载后没有明确把焦点移入；没有焦点循环、Escape 关闭，也没有关闭后的焦点恢复。声明模态语义本身不会自动阻止键盘焦点进入背景页面。

**目标**：

键盘和辅助技术用户出现提示时，能立即理解弹窗内容、执行现有操作或稍后关闭；关闭后焦点落在合理的现有页面位置。

**实施步骤**：

1. 弹窗插入 DOM 后，将焦点移入弹窗。默认焦点可放在“开始今日一题”按钮；不得自动触发该按钮。
2. 在弹窗打开期间捕获 Tab / Shift+Tab：焦点留在弹窗的可操作项内循环；若弹窗因加载暂时禁用主按钮，仍保持可达的关闭操作。
3. 支持 Escape 触发与“稍后再说”等价的关闭动作。点击遮罩关闭如保留，需继续确保恢复焦点。
4. 保存触发弹窗时的活动元素。关闭时若该元素仍在文档中则恢复焦点；如果它已因路由返回首页而卸载，则聚焦首页中“今日一题”现有按钮，必要时聚焦 `main#view`（需设置合适的 `tabindex`）。
5. “开始今日一题”请求中维持当前禁用和加载文本逻辑；失败时恢复按钮并让错误可读；成功启动做题后不尝试把焦点抢回被卸载弹窗。
6. 弹窗开放期间，读屏器应读出标题和说明；焦点不能落到遮罩后面的导航或页面按钮。
7. 处理重复打开保护和清理事件监听，确保关闭后不存在遗留 keydown handler。

**验收标准**：

- 通过键盘触发弹窗后，焦点自动进入弹窗；Tab / Shift+Tab 不会跳到背景页面。
- Escape 和“稍后再说”都关闭弹窗，焦点返回合理位置。
- Enter / Space 可触发现有按钮；“开始今日一题”最多请求一次。
- 抽题失败、题库为空、抽题成功三种场景均可继续操作，没有焦点丢失或永久禁用。
- 弹窗关闭后再次打开仍可正常操作，无重复监听造成的多次处理。
- 原有每日状态判断、受限路由集合、完成判定和抽题流程完全不变。

### PAGE-03：移动“全部功能”页定向观察（条件任务）

**现状定位**：

- `static/m/m.js` 的 `HUB` 和 `renderAll()`。
- 页面已有分组标题、名称和简短描述；这是当前评估中的减轻因素。

**目标**：

用少量任务观察判断入口列表是否真的难找，避免仅因项目功能多就新增筛选或改版。

**观察步骤**：

1. 邀请 3–5 名未参与开发或不熟悉代码的使用者；如果无法找到参与者，由开发者以“首次使用者”身份执行并标注为自测，不得称为用户研究。
2. 给出 3 个具体任务，不提示分类名称，例如：
   - 找到“复习今天到期的题目”；
   - 找到“查某个考点的速算方法”；
   - 找到“查看自己导入的题目”。
3. 记录每项任务是否完成、从进入功能页到点击目标入口的耗时、是否误入其他页面、参与者的原话。
4. 观察时不解释分类含义，也不引导视线；发生误解时记录，不立即提示正确答案。
5. 只有当多名参与者在同一类任务中重复出现明显困难时，才提交导航调整建议。建议先比较“分组标题/说明文案/顺序调整”等低成本方案，再考虑额外筛选控件。

**条件验收**：

### 7.4 顺带发现（不在本轮范围，未修改）

`scripts/e2e_mobile.py` 的「启动首页渲染」断言在**多次重跑中出现约 1/3 概率失败**，报
`加载失败：attempt to write a readonly database`（`/api/stats`、`/api/paper-drafts` 返回 500）。

- **已确认与本轮改动无关**：用 `git worktree add --detach .tmp/base_head HEAD` 建出干净基线，
  跑同一份 E2E，**逐字复现同一处失败**（同样的 hash、同样的 view 文案）。
- **根因**：手机端多身份路径下个人库为 WAL 模式，首页首屏会并发打多个接口；当最后一条连接关闭触发
  checkpoint 并删除 `-wal` / `-shm` 时，另一条仍映射旧 `-shm` 的连接的下一次写入会报只读。
  触发语句为 `CREATE TABLE IF NOT EXISTS mastery(...)`（`IF NOT EXISTS` 同样需要写锁）。
  这与 `app/db.py` 中 `_decay_worker` 的注释描述的正是同一个竞态——该处已有「换新连接重试」兜底，
  但**请求路径没有对应的重试**。
- **建议（后续单独处理，本轮不动）**：在请求路径的 `connect()` / `_ensure_mastery` 上做一次只读错误重试，

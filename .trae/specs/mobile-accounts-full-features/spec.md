# GOSHORE 手机版：本地多账号 + 网页全功能移植 - 产品需求文档

## Overview
- **Summary**: 在现有安卓独立版 App（单用户、离线、Chaquopy + 内置 HTTP 服务 + WebView）基础上，新增**本地注册/登录体系**（每人学习数据独立），并将桌面网页版的**全部 21 个功能**移植到手机端（含需要联网的 AI 类功能）。
- **Purpose**: App 会分发给多位备考者共用同一安装包，且可能出现一台手机多人交替使用；每个人需要有自己的账号、做题记录、错题本、复习计划与设置，互不干扰。
- **Target Users**: 事业单位联考 C 类备考者（用户本人及同学/家人），使用 arm64 安卓手机。

## Goals
- 本地账号体系：注册、登录、登出、切换账号，全程无需服务器、离线可用。
- 每个账号拥有独立的学习数据：作答记录、错题/错因、收藏、复习计划、速算/列式/词语填空记录、辨析卡、申论批改记录、疑点、设置与 AI Key。
- 桌面网页版 5 组 21 个功能在手机端全部可打开、可完成核心操作。
- AI 类功能（AI 讲题、AI 批改、AI 变式/错因建议等）在手机联网且配置了 API Key 时可用；无网络/无 Key 时有明确提示。
- 覆盖安装新版本不丢失已有学习数据（现有数据自动迁入"游客"身份）。
- 桌面端功能与做题规则保持完全不变。

## Non-Goals
- 不做在线云账号、云端同步、跨设备数据迁移（可用本地备份/恢复在手机间搬家）。
- 不做手机号短信验证、第三方登录（微信/QQ）、图形验证码。
- 不做账号找回服务（本地账号体系无法服务端找回；提供"本地备份"作为数据兜底手段）。
- 不改变题库内容与做题判分规则。

## Background & Context
- 现有架构：Java(MainActivity) 首启解压 assets/payload.zip（goshor.db + img/）→ Chaquopy 启动 Python → goshor_server.py（标准库 http.server，127.0.0.1 随机端口）→ WebView 加载。
- 桌面功能清单（static/index.html 导航、static/app.js 渲染）：
  - 总览：今日、周报、做题记录
  - 行测精练：组卷、判断专项、列式专项、词语填空、速算
  - 综应专区：申论综应、科技文献、时政、AI批改
  - 复习巩固：今日复习、错题本、收藏、辨析卡
  - 题库管理：题库(搜题)、疑点、导入、设置
- 手机端现状：首页、刷题(组卷/做题/材料卡/填空横线)、复习(错题本+列式专项)、我的(周报+收藏入口)；服务器仅实现约 10 个端点。
- 数据表分两类：**共享内容表**（documents 题库、shizheng 时政库）与**个人数据表**（answers、marks、speed_rounds、speed_items、wordfill_questions/answers、wrong_reasons、review_plan、cards/card_reviews/card_plan、essay_grades、formula_rounds/items、doubts、explain_cache）。
- 手机库已删除 docs_fts 全文索引，搜题需用 LIKE 模糊匹配替代。
- AI 调用（app/ai.py 等）依赖 httpx，DeepSeek 兼容接口，Key 存在 settings 中；桌面用 Windows DPAPI 加密，安卓目前为沙箱内明文。
- 用户偏好：中文沟通、实用优先、大功能先确认、每个功能需实际跑通验证。

## Functional Requirements

### 账号体系
- **FR-1**: 新用户可注册账号：用户名（≥2 字符，全站唯一，大小写敏感按字面）+ 密码（≥6 字符）。注册时可选择"把当前游客的学习记录迁入本账号"。
- **FR-2**: 已注册用户可用用户名+密码登录；登录后该账号的全部学习数据可用，其他账号（含游客）数据不可见。
- **FR-3**: 可登出/切换账号；登出后回到登录页，也可以"以游客身份继续"。
- **FR-4**: App 始终存在"游客"身份（uid=0）；未登录时所有数据产生在游客名下。
- **FR-5**: 密码以加盐哈希存储（PBKDF2-HMAC-SHA256），任何接口不返回密码与哈希。
- **FR-6**: 会话在 App 重启后保持（记住上次登录身份）；直到主动登出。
- **FR-7**: 老版本升级覆盖安装后，原有的全部个人数据自动完整迁入游客身份，数量可核对。

### 功能移植
- **FR-8**: 手机端提供 21 个功能的入口（按 5 组组织），每个页面可正常打开、无空白页/无报错。
- **FR-9**: 各功能核心操作可用，判分/计时/落库规则与桌面端一致：
  - 组卷、判断专项、列式专项、词语填空、速算：生成 → 作答 → 判分 → 记录可查。
  - 今日复习、错题本、收藏、辨析卡：列表/重做/标注操作可用。
  - 申论综应、科技文献、时政、AI批改：材料/题目可读，作答与（满足条件时的）AI 流程可用。
  - 题库搜题：关键词模糊搜索可返回结果并打开题目；疑点：列出/状态变更可用；导入：JSON/网页预览与提交可用；设置：读写可用。
- **FR-10**: AI 功能在联网 + 已配置 Key 时正常返回（讲题内容流式展示）；未配置 Key 或无网络时给出可理解的中文提示，不崩溃。
- **FR-11**: 每个账号的 AI Key 与设置独立；切换账号后设置随之切换。
- **FR-12**: 支持本地备份导出/导入（含个人学习数据；默认不导出 API Key），可用于换机。

## Non-Functional Requirements
- **NFR-1**: 注册/登录/登出/切换在普通手机上 1 秒内完成；切换账号后列表数据立即反映新身份。
- **NFR-2**: 新增多账号后，App 每增加一个账号的额外存储 ≤ 5 MB（个人数据为纯文本记录；不为每个账号复制题库与图片）。
- **NFR-3**: 最终 APK 体积增量 ≤ 30 MB（主要为 httpx 依赖）。
- **NFR-4**: 手机端全部页面 JS 错误为 0，App 无因新功能导致的崩溃。
- **NFR-5**: 桌面端启动与现有回归（编译检查 + API 冒烟 + 页面无头验证）全部通过，行为零变化。
- **NFR-6**: 账号数据文件存放于 App 私有目录，其他 App 不可访问；API Key 不出现在备份导出与任何接口返回中。
- **NFR-7**: 手机端保持书房纸墨视觉风格，交互方式符合手机习惯（触屏、返回键、底部导航）。

## Constraints
- **Technical**: 仅标准库 + 现有 app 模块 + httpx（Chaquopy pip）；不引入 FastAPI/pydantic（无可靠安卓轮子）；服务仍只监听 127.0.0.1；ABI 仍为 arm64-v8a、x86_64。
- **Business**: 离线优先；无服务器运行成本；AI 费用由用户自己的 API 账号承担。
- **Dependencies**: Chaquopy 16.1.0 / Python 3.13；httpx 及其依赖需有 Chaquopy 可用轮子；现有数据产物流程 scripts/build_mobile_assets.py。

## Assumptions
- 一台手机注册账号数量很少（≤ 5 个），按此规模做性能与存储设计。
- 用户理解本地账号不支持云端找回，愿意通过备份功能保护数据。
- 题库（documents）与时政库（shizheng）对所有账号只读共享；导入的新题目归入当前账号私有集合。
- 安卓沙箱隔离足以保护 API Key 与密码哈希，不再额外做密钥派生加密（如后续需要可单独增强）。

## Acceptance Criteria

### AC-1: 注册成功并生成独立数据空间
- **Type**: `rule`
- **Given**: 设备上存在游客数据且无同名账号
- **When**: 以合法用户名（≥2 字符）、合法密码（≥6 字符）注册，可勾选迁入游客数据
- **Then**: 注册成功，自动登录为新账号；勾选迁入时游客原有作答/错题/收藏等全部出现在新账号名下，游客数据清空
- **Pass Condition**: 新账号接口返回本人信息；迁移数据条数与迁移前游客条数一致；重复用户名、过短用户名/密码被拒绝并给出中文提示
- **Evidence**: CDP 自动测试记录（注册接口返回、各数据表条数对比、拒绝用例返回）

### AC-2: 登录校验与账号隔离
- **Type**: `rule`
- **Given**: 设备上至少有两个已注册账号 A、B（各自有可区分的作答/收藏/错题数据）
- **When**: 分别登录 A、B 查看首页、错题本、收藏、做题记录
- **Then**: 每个账号只能看到自己的数据；错误密码登录被拒绝
- **Pass Condition**: A 与 B 的统计数字、错题列表、收藏列表互不重叠；错误密码返回明确错误且登录态不变
- **Evidence**: CDP 测试中切换账号后的接口返回对比（按 doc_id 集合比对）

### AC-3: 登出与游客身份
- **Type**: `rule`
- **Given**: 用户已登录某账号
- **When**: 执行登出
- **Then**: 回到登录页；选择"游客继续"后产生的数据属于游客且不影响已登录账号；杀掉 App 重开后仍保持上次身份
- **Pass Condition**: 登出后接口显示游客身份；游客新数据在该账号视角不可见；重启后 /api/auth/me 显示登出前的身份
- **Evidence**: CDP 测试 + 重启 App 后接口返回

### AC-4: 老版本数据迁移
- **Type**: `rule`
- **Given**: 手机上安装旧版 App 且已产生做题数据（如 16 条作答、6 道错题）
- **When**: 用新版 APK 覆盖安装并启动
- **Then**: 旧数据完整出现在游客名下
- **Pass Condition**: 迁移后游客 answers/marks/review_plan 等条数 ≥ 旧库条数，首页统计数字与升级前一致
- **Evidence**: 升级前后统计接口返回对比（模拟器执行：装旧版→做题→装新版→核对）

### AC-5: 21 个功能全部可用
- **Type**: `rule`
- **Given**: 已登录账号
- **When**: 逐个打开 21 个功能入口
- **Then**: 每个页面成功渲染核心内容，无空白页、无接口 404/500、无 JS 错误
- **Pass Condition**: 21/21 页面渲染检查通过，logcat 无 JS ERROR
- **Evidence**: CDP 逐页探测脚本输出 + logcat 记录

### AC-6: 核心做题链路判分一致
- **Type**: `rule`
- **Given**: 已登录账号
- **When**: 分别在组卷（真题）、判断专项、列式、词语填空、速算中完成至少一轮作答
- **Then**: 判分（对/错标色）、计时、记录入库与桌面端规则一致；错题自动进入错题本/复习计划
- **Pass Condition**: 5 条链路全部跑通且作答后统计数字相应增加
- **Evidence**: CDP 自动化实际作答记录（对错标色断言 + 前后统计对比）

### AC-7: AI 功能在线可用与离线提示
- **Type**: `rule`
- **Given**: 两种环境：已配置 Key 且联网 / 未配置 Key（或断网）
- **When**: 使用 AI 讲题或 AI 批改
- **Then**: 在线时正常返回 AI 内容（流式可见、无乱码）；离线/无 Key 时显示明确中文提示，页面不崩溃、无未捕获异常
- **Pass Condition**: 两种环境各至少一个用例符合预期，0 JS 未捕获错误
- **Evidence**: CDP 测试输出（含真实 API 调用结果或超时判定）+ 截图

### AC-8: 备份与恢复
- **Type**: `rule`
- **Given**: 账号下有学习数据
- **When**: 导出备份、清空后导入备份
- **Then**: 数据恢复到导出时状态；导出文件不含 API Key 明文
- **Pass Condition**: 恢复后关键表条数一致；备份内容检索不到 Key 字段值
- **Evidence**: CDP/进程内测试脚本输出（条数对比 + 备份内容检查）

### AC-9: 体积与存储增量
- **Type**: `rule`
- **Given**: 新版 APK 构建完成
- **When**: 检查 APK 大小，注册第 2 个账号后查看用户数据目录大小
- **Then**: APK 增量 ≤ 30 MB；新增账号数据文件 ≤ 5 MB
- **Pass Condition**: 测量值满足阈值
- **Evidence**: 文件大小测量命令输出

### AC-10: 桌面端零回归
- **Type**: `rule`
- **Given**: 完成全部代码改动
- **When**: 运行桌面端回归流程
- **Then**: 编译检查、API 冒烟、页面无头验证全部通过
- **Pass Condition**: 回归结果全绿
- **Evidence**: 回归技能执行输出

### AC-11: 手机端视觉与交互质量
- **Type**: `rubric`
- **Dimension**: 手机端可用性与视觉一致性（导航清晰度、纸墨风一致性、触屏操作流畅度、返回逻辑正确性）
- **Scale**: 1-5
- **Anchors**: 1 = 页面错乱或无法操作；3 = 功能可用但视觉/交互明显粗糙；5 = 与现有手机页同样精致、操作直观
- **Pass Threshold**: >= 4
- **Evidence**: 每个功能分组至少 1 张截图 + 人工/评审评分记录
